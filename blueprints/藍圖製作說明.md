# 藍圖製作說明（寫給 AI 看的）

你的任務：**看一張圖片（或一段文字描述），產生一支藍圖 `.js` 檔**，放進這個資料夾，
遊戲下次開啟就會把它加進建築清單（**排在下拉選單最前面**），跟內建的 48 座一樣可以蓋、可以拆。

做完要交付兩件事，缺一不可：

1. 新檔案 `blueprints/<名字>.js`
2. 在 `blueprints/list.js` 的陣列裡加上那個檔名

> 為什麼要第 2 步：遊戲是用 `file://` 直接開的（不架伺服器），
> 而 `file://` 沒辦法列出資料夾內容——`fetch` 會被 CORS 擋掉。所以檔名得自己列。

---

## 1. 核心觀念：造型要用函式「按尺寸重畫」，不是畫一張固定的圖

遊戲的建材數是**可調的（300–3000 塊）**，同一座建築要能是小屋也能是大宅。
所以藍圖不是一份靜態模型，而是**一個吃尺度參數 `s` 的函式**：

```js
gen(v, s) { ... }        // 每個尺寸都用 s 重新算一次寬高，重畫一次
```

遊戲會掃 `s`（`fitScale()`），找出讓格數最接近玩家設定的那個尺寸，再呼叫你的 `gen`。
**你不用管玩家設多少塊**，只要保證「`s` 大房子就大」。

這件事非做不可的理由：如果你把造型寫死成固定解析度（例如一張字元圖），
縮小時就只能靠抽樣，**1 格厚的牆會被整片抽掉**——實測範例小木屋用字元圖版縮到 300 塊時，
正面與側面兩片牆整個消失，只剩四根角柱撐著屋頂。參數化重畫不會有這個問題：
同一棟房子在 300 塊時是小屋、3000 塊時是大宅，門、窗、屋簷、煙囪一個都不會少。

## 2. 檔案長什麼樣

一支檔案 = 呼叫一次 `customBlueprint({...})`：

```js
customBlueprint({
  name: '我的塔',                              // 下拉選單上的名字，不能跟現有的撞號
  pal: ['#cfc7b8', '#8d8f92', '#c0483c'],      // 顏色表，格子的 c 就是這個陣列的索引
  lo: 4, hi: 20,                               // s 的掃描範圍（見第 5 節）

  gen(v, s) {
    const r = Math.max(3, Math.round(s * 0.4));      // 半徑跟著 s 長
    const h = Math.max(6, Math.round(s * 2));        // 高度跟著 s 長
    v.cyl(0, 0, 0, r, h, 0, 2);                      // 中空圓柱，牆厚 2
    v.cyl(0, h, 0, r + 1, 1, 1);                     // 頂端一圈簷
    v.taper(0, h + 1, 0, r + 1, 0.5, r * 2, 2);      // 收尖的屋頂
  }
});
```

**座標系**：

| 東西 | 意義 |
|---|---|
| `x`、`z` | 水平面。**原點在中心**，可以是負的（遊戲會自己抓包圍盒置中） |
| `y` | 高度，**從 0 往上**。`y < 0` 的格子會被直接忽略 |
| `c` | `pal` 的索引（0 開始）。同一格重複寫，**後寫的蓋掉先寫的** |

「先填實心、再挖洞」是常用手法，靠的就是後寫蓋先寫。

## 3. 能用的方法（`v` 的完整清單）

| 方法 | 做什麼 |
|---|---|
| `box(x0, y0, z0, w, h, d, c)` | 實心長方體。`x0`/`z0` 是**中心**，`y0` 是**底面所在層** |
| `walls(x0, y0, z0, w, h, d, c, t)` | 只留四面牆，`t` 是牆厚（預設 1）。**蓋房子的主力** |
| `carve(x0, y0, z0, w, h, d)` | 挖掉一塊長方體（門、窗洞、拱門） |
| `cyl(x0, y0, z0, r, h, c, hollow)` | 圓柱。`hollow` 給牆厚就只留外環 |
| `taper(x0, y0, z0, r0, r1, h, c, shell)` | 底半徑 `r0` 收到頂半徑 `r1`。`shell` 給牆厚就中空 |
| `pyramid(x0, y0, z0, b, c, step)` | 階梯方錐，底邊 `b`，每層縮 `step` 格（預設 1） |
| `gable(x0, y0, z0, w, d, c)` | 山牆屋頂：`w` 每層縮 2 格、`d` 不變（房子、神廟） |
| `dome(x0, y0, z0, r, c, squash)` | 圓頂（只做殼，實心太吃積木）。`squash` < 1 是扁的 |
| `onion(x0, y0, z0, r, h, c)` | 洋蔥頂：先鼓出來再收尖（俄式教堂） |
| `eave(x0, y0, z0, w, d, c, layers)` | 屋簷：一圈比下面寬的簷邊（東方建築的關鍵） |
| `ellipseRing(x0, y0, z0, rx, rz, h, c, thick)` | 橢圓環（競技場、圓形底座） |
| `line(x0, y0, z0, x1, y1, z1, c)` | 兩點之間拉一條線（斜撐、吊索） |
| `set(x, y, z, c)` / `del(x, y, z)` / `has(x, y, z)` | 單格寫入／刪除／查詢 |

另外有個現成的對稱小工具：`corners4(v, dx, dz, fn)`——在 `(±dx, ±dz)` 四個角各跑一次 `fn(v, x, z)`。

## 4. 怎麼從圖片做出來

1. **把圖片拆成幾何體**。先問「這棟東西是由哪幾塊組成的」：底座、主體、屋頂、塔尖、附屬物。
   一棟房子就是「地板 + 四面牆 + 壓頂 + 山牆屋頂 + 煙囪」五件事，五行 `v.xxx()` 就寫完了。
2. **每一塊都用 `s` 算尺寸，不要寫死數字**。量圖片上的比例（寬:高:深大約多少），
   換成係數：`const w = Math.round(s * 2.0)`、`const h = Math.round(s * 0.9)`。
   係數之間的比例就是這棟建築的長相，`s` 只負責整體大小。
3. **每一塊都要有下限**：`Math.max(5, Math.round(s * 2))`。
   不然 `s` 小的時候會算出 0 或 1，造型直接消失。
4. **對齊要注意奇偶**。靠中線對稱的東西（屋脊、塔尖、正門）寬度要取奇數：`| 1`。
   偶數的話中心會落在兩格之間，整個偏半格。
5. **顏色分區塊給**，抓圖片的 3–6 個主色寫進 `pal`。深色留給底座與陰影面，亮色留給屋頂與招牌。
   不要一格一色做漸層——voxel 的顆粒感就是它的味道。
6. 存檔、把檔名加進 `list.js`、照第 6 節量一次。

參考 `範例-小木屋.js`：五個部件、每個都掛在 `s` 上，300 塊與 3000 塊是同一棟房子。
更複雜的造型直接看 `src/blueprints.js` 裡那 48 座怎麼寫的。

## 5. `lo` / `hi` 要給多少

`lo`／`hi` 是 `s` 的掃描範圍。遊戲會在這中間找「格數最接近目標」的那個 `s`，所以：

- **`lo`**：讓建築剛好約 **300 格**的那個 `s`（玩家能設的最小值）
- **`hi`**：讓建築約 **3000 格**的那個 `s`（最大值）

給寬一點沒關係（掃描會自己停），但**範圍如果沒涵蓋到目標，塊數就永遠差一截**。
尺寸上限抓 **48×48×48**，超過就開始吃效能、遠看也分不出細節。

塊數會**一階一階跳**（`Math.round()` 與 `| 1` 造成的），階與階之間就是誤差。
階距太大時（實測某個係數組合讓 1600 塊只能挑到 1783，差 11%），把**跳最兇的那個維度**
係數調小一點：讓它跳得少一點、由別的維度連續變化去補。
不必所有維度都取奇數——只有真的要對稱的那一個需要。

## 6. 交出去之前自己量一次

開 `index.html`，F12 貼這段，看實得塊數跟目標差多少：

```js
const i = SHAPES.findIndex(s => s.n === '我的塔');
[300, 800, 1600, 3000].forEach(t =>
  console.log(t, '→', makeBlueprint(i, t).slots.length, ' s=' + fitScale(SHAPES[i], t).toFixed(2)));
```

檢查清單：

- [ ] `name` 沒有跟內建的 48 座或其他自訂藍圖撞號
- [ ] 每個尺寸都畫得出來：300、1600、3000 都試過，偏差大致在 10% 以內
- [ ] **300 塊時造型還認得出來**（門窗屋簷都在，不是一坨方塊）
- [ ] 有貼地的格子（`y = 0`）。遊戲的垮塌判定是從地面往上做連通性搜尋
- [ ] 所有尺寸都用了 `Math.max(下限, ...)`，小尺寸不會有部件消失
- [ ] `pal` 的顏色數 ≥ 你用到的最大 `c` + 1
- [ ] 檔名已經加進 `blueprints/list.js`
- [ ] console（F12）沒有 `[自訂藍圖]` 開頭的警告

**懸空部件是允許的**（風車扇葉、拱門下方的空洞），不會平白掉下來；
但它們是靠附近的積木撐著，附近被打掉就會整組掉——這是遊戲的一部分，不用避開。

## 附錄：字元圖（`layers`）

不想寫函式時，可以改給一疊字元圖，載入時會幫你包成一個會縮放的 `gen`：

```js
customBlueprint({
  name: '小方塊',
  pal: ['#c8a06a', '#c0483c'],
  layers: [
    ['111',        // layers 的索引 = y（高度），layers[0] 是貼地那層
     '111',        // 一層裡字串的索引 = z（往畫面深處）
     '111'],       // 字串裡字元的索引 = x（往右）
    ['2.2',        // 1–9 = pal 的第 1–9 個顏色；. 空白 0 = 空的
     '...',
     '2.2']
  ]
});
```

不用給 `lo`／`hi`，會由基準格數自動反推（基準抓 200～600 格）。

**但這條路只適合草稿。** 它是對一張固定解析度的圖做最近鄰重取樣，
縮小時**細瘦的部件會被整片抽掉**——1 格厚的牆、1 格寬的柱子、窗框都可能消失。
要讓建築在 300 塊跟 3000 塊都好看，還是回去寫 `gen(v, s)`。
