# 藍圖製作說明（寫給 AI 看的）

你的任務：**看一張圖片（或一段文字描述），產生一支藍圖 `.js` 檔**，
玩家把它放進遊戲的 `blueprints/` 資料夾，下次開啟就會出現在建築清單最前面，
跟內建的 48 座一樣可以蓋、可以拆。

**你看不到遊戲的原始碼——這份文件就是全部。** 需要的函式、座標系、限制、
以及你會收到的診斷報告怎麼讀，下面都寫了。不要引用這份文件以外的東西。

---

## 0. 輸出格式（照這個給，不然玩家沒辦法用）

**整份藍圖包成「一個」程式碼區塊**，玩家按一次複製鈕就全部拿得走：

<pre>
```js
// 檔名：我的城堡.js
customBlueprint({
  name: '我的城堡',
  ...
});
```
</pre>

- 區塊**第一行寫檔名註解**（`// 檔名：xxx.js`），它本身就是合法的 JS，貼進遊戲也不會出事。
- 區塊裡只有這支 `.js` 的內容：不要 `import`／`export`／`module.exports`／`window.xxx =`。
- **不要拆成兩個區塊**，也不要把程式碼的一部分留在區塊外面。
- 區塊**外面**只寫給人看的提醒（不必複製的那些）：
  1. 把檔案存進 `blueprints/`
  2. 在 `blueprints/list.js` 的陣列裡加上那個檔名

> 為什麼是「包成一個區塊」而不是「完全不要圍籬」：聊天介面碰到程式碼一定會自己裝框，
> 硬要求純文字的結果通常是「檔名在框外、程式碼在框內」——玩家得複製兩次，還常常漏掉一半。
> 包成一個區塊就只有一個複製鈕。預覽頁的貼上框會自動吃掉 <code>```js</code> 圍籬與
> 「檔名：」那一行，所以**連框帶內容整段貼進去就能用**。

> 為什麼要第 2 步：遊戲是用 `file://` 直接開的（不架伺服器），
> 而 `file://` 沒辦法列出資料夾內容——`fetch` 會被 CORS 擋掉。所以檔名得自己列。

## 1. 核心觀念：造型要用函式「按尺寸重畫」，不是畫一張固定的圖

遊戲的建材數是**可挑的（面板三檔：1800／3000／9000 塊，體檢還會多量 300 與 10000 兩個極端）**，
同一座建築要能是小屋也能是大宅。
所以藍圖不是一份靜態模型，而是**一個吃尺度參數 `s` 的函式**：

```js
gen(v, s) { ... }        // 每個尺寸都用 s 重新算一次寬高，重畫一次
```

遊戲會掃 `s`，找出讓格數最接近玩家設定的那個尺寸，再呼叫你的 `gen`。
**你不用管玩家設多少塊**，只要保證「`s` 大房子就大」。

這件事非做不可的理由：造型寫死成固定解析度（例如一張字元圖）的話，
縮小時只能靠抽樣，**1 格厚的牆會被整片抽掉**——實測一棟小木屋用字元圖版縮到 300 塊時，
正面與側面兩片牆整個消失，只剩四根角柱撐著屋頂。參數化重畫不會有這個問題：
同一棟房子在 300 塊是小屋、3000 塊是大宅，門、窗、屋簷、煙囪一個都不會少。

## 2. 檔案骨架與座標系

```js
customBlueprint({
  name: '我的塔',                              // 選單上的名字，不能跟現有的撞號
  pal: ['#cfc7b8', '#8d8f92', '#c0483c'],      // 顏色表，格子的 c 就是這個陣列的索引
  lo: 2.5, hi: 12,                             // s 的掃描範圍（見第 6 節）

  gen(v, s) {
    const r = dim(s, 0.4, 3);                  // 半徑跟著 s 長，下限 3
    const h = dim(s, 2.0, 6);                  // 高度跟著 s 長，下限 6
    v.cyl(0, 0, 0, r, h, 0, 2);                // 中空圓柱，牆厚 2
    v.cyl(0, h, 0, r + 1, 1, 1);               // 頂端一圈簷
    v.taper(0, h + 1, 0, r + 1, 0.5, r * 2, 2);// 收尖的屋頂
  }
});
```

| 東西 | 意義 |
|---|---|
| `x`、`z` | 水平面。**原點在中心**，可以是負的（遊戲會自己抓包圍盒置中） |
| `y` | 高度，**從 0 往上**。`y < 0` 的格子會被直接忽略 |
| `c` | `pal` 的索引（0 開始）。同一格重複寫，**後寫的蓋掉先寫的** |

「先填實心、再挖洞」是常用手法，靠的就是後寫蓋先寫。

**不必自己保證 `y = 0` 有格子**：遊戲會把整份藍圖最低那一層貼到地面。
要在意的是「最底層有幾格」——只靠一兩格站著的話，那幾格一掉就整棟報廢。

**懸空部件是允許的**（風車扇葉、拱門下方的空洞、吊索），不會平白掉下來；
它們靠附近的積木撐著，附近被打掉就會整組掉——這是遊戲的一部分，不用避開。

## 3. 能用的函式

### 3.1 `v` 的方法（畫格子）

| 方法 | 做什麼 |
|---|---|
| `v.box(x0, y0, z0, w, h, d, c)` | 實心長方體。`x0`/`z0` 是**中心**，`y0` 是**底面所在層** |
| `v.walls(x0, y0, z0, w, h, d, c, t)` | 只留四面牆，`t` 是牆厚（預設 1）。**蓋房子的主力** |
| `v.carve(x0, y0, z0, w, h, d)` | 挖掉一塊長方體（門、窗洞、通道） |
| `v.cyl(x0, y0, z0, r, h, c, hollow)` | 站著的圓柱。`hollow` 給牆厚就只留外環 |
| `v.taper(x0, y0, z0, r0, r1, h, c, shell)` | 底半徑 `r0` 收到頂半徑 `r1`。`shell` 給牆厚就中空 |
| `v.pyramid(x0, y0, z0, b, c, step)` | 階梯方錐，底邊 `b`，每層縮 `step` 格（預設 1） |
| `v.gable(x0, y0, z0, w, d, c)` | 山牆屋頂（兩坡）：`w` 每層縮 2 格、`d` 不變 |
| `v.dome(x0, y0, z0, r, c, squash)` | 圓頂（只做殼，實心太吃積木）。`squash` < 1 是扁的 |
| `v.onion(x0, y0, z0, r, h, c)` | 洋蔥頂：先鼓出來再收尖（俄式教堂） |
| `v.eave(x0, y0, z0, w, d, c, layers)` | 屋簷：一圈比下面寬的簷邊（東方建築的關鍵） |
| `v.ellipseRing(x0, y0, z0, rx, rz, h, c, thick)` | 橢圓環（競技場、圓形底座） |
| `v.line(x0, y0, z0, x1, y1, z1, c)` | 兩點之間拉一條線（斜撐、吊索） |
| `v.set(x, y, z, c)` / `v.del(x, y, z)` / `v.has(x, y, z)` | 單格寫入／刪除／查詢 |

### 3.2 組合工具（直接呼叫，不用加 `v.`，但第一個參數要傳 `v`）

| 函式 | 做什麼 |
|---|---|
| `dim(s, 係數, 下限, 奇數?)` | **算尺寸都用這支**：`= Math.max(下限, Math.round(s * 係數))`，第四個給 `true` 會逼成奇數。忘了給下限是最常見的失敗 |
| `corners4(v, dx, dz, fn)` | 在 `(±dx, ±dz)` 四個角各跑一次 `fn(v, x, z)`（角塔、四根柱子） |
| `mirrorX(v, dx, fn)` / `mirrorZ(v, dz, fn)` | 左右／前後對稱各跑一次 `fn(v, 偏移)` |
| `ringOf(v, n, r, fn, x0, z0, a0)` | 把 `n` 個東西平均排成一圈，`fn(v, x, z, 角度, 第幾個)`（柱廊、輻條） |
| `arch(v, x0, y0, z0, w, h, t, c)` | 拱門。`w` 開口寬（自動取奇數）、`h` 直柱段高、`t` 牆厚（沿 z）。`c` 給了會先補一片牆再挖，不給就只挖（用在已經有牆的立面上） |
| `archRow(v, x0, y0, z0, n, w, h, t, pier, c)` | 一排 `n` 個拱，中間隔著寬 `pier` 的柱子。回傳整排總寬 |
| `stairs(v, x0, y0, z0, n, wide, dir, c)` | 階梯，`dir` 是 `'x'`／`'-x'`／`'z'`／`'-z'`。每階都填實到底，不會變成懸空踏面 |
| `hipRoof(v, x0, y0, z0, w, d, c)` | 四坡屋頂（`gable` 只收寬，這支寬深一起收） |
| `tubeZ(v, x0, y0, z0, r, len, c, hollow)` | 躺著的圓柱（沿 z）：火車鍋爐、飛機機身 |
| `wheelX(v, x0, y0, z0, r, t, c, rim)` | 輪子：圓面立在 y–z 平面、厚度沿 x。`rim` 給了外圈換色 |
| `blob(v, x0, y0, z0, rx, ry, rz, c, shell)` | 橢球（動物軀幹、頭）。半徑**不要取整**，塊數才會隨尺度連續變化 |
| `tint(v, x, y, z, c)` | 只在「已經有積木」的格子上換色，回傳有沒有換到 |
| `paintFrom(v, x, y, z, dx, dy, dz, n, c)` | 從外面往裡掃最多 `n` 格，找到第一格實心的就換色 |

**曲面上的裝飾（眼睛、斑紋、圓頂上的窗）一律用 `tint` 或 `paintFrom`，不要用 `v.set`**：
曲面上算出來的座標常常落在空氣裡，`v.set` 會在那裡長出一顆孤立的懸空格。

**參數少給會被擋下來**：上面每一支都會在進來時驗一次參數，少給、或算出 `NaN`／`undefined`
就丟例外，診斷報告會直接寫「`v.box(x0, y0, z0, w, h, d, c)` 的第 7 個參數 `c` 沒給」。
表格裡沒有標「預設 …」「不給就 …」的參數就是**必要的**——尤其是最後那個顏色 `c`，
它是最常忘的一個。

### 3.3 參數多的兩支改吃具名物件

十個位置參數排錯一個就整片跑掉，而且看不出哪裡錯，所以這兩支給的是物件：

```js
// 立面窗陣列：{x,y,z} 是第一排最中間那格所在的牆面位置
windowGrid(v, { x: 0, y: 4, z: -r, cols: 3, rows: 5,
                stepX: 3, stepY: 4, w: 1, h: 2, c: 3, axis: 'x' });
// axis: 'x'（預設，窗沿 x 排在朝 ±z 的牆上）或 'z'（沿 z 排，側面兩片牆）
// 走 tint，所以牆不在那裡就什麼都不會畫；回傳真的畫上去幾格（0 = 位置猜錯了）

// 斜撐格架：兩根柱子之間拉 n 段交叉斜撐（鐵塔、桁架橋）
lattice(v, { x0: -8, z0: 0, x1: 8, z1: 0, y: 0, h: 20, n: 5, c: 1 });
```

## 4. 三個完整範例

三支都是實測過的：塊數偏差在 10% 以內，沒有部件消失、沒有孤島。
第一支是**細節密度的標準**（十四個部件），後兩支示範另外兩種造型的做法。

### 4.1 多部件建築（哥德式小教堂）

**這一支就是 `blueprints/` 裡附的那份範例**，也是「細節密度」的標準：
台基、牆、扶壁、長窗、壓頂、屋頂、鐘樓、大門、玫瑰窗、鐘室開口、小尖塔、尖頂、十字架、台階——
十四個部件，每個只有一到三行。**像不像幾乎全靠部件數，不是靠塊數。**
實測 1600／3000／10000 塊三檔偏差都在 2% 以內，六種顏色在最小尺寸也一個都沒少。

```js
customBlueprint({
  name: '小教堂',
  pal: ['#d8d0c0',   // 0 石牆（亮）
        '#9c9384',   // 1 台基、扶壁、簷（暗一階，用來分層）
        '#4a5a68',   // 2 屋頂與尖頂
        '#bfe0f2',   // 3 窗玻璃
        '#d9a441',   // 4 玫瑰窗外框、小尖塔、十字架
        '#6b4a2f'],  // 5 木門
  lo: 2.2, hi: 15.5,

  gen(v, s) {
    const nw = dim(s, 1.50, 7, true);     // 中殿寬（奇數：屋頂每層縮 2 格）
    const nd = dim(s, 2.05, 9);           // 中殿深
    const nh = dim(s, 1.25, 4);           // 中殿牆高
    const tw = dim(s, 0.85, 5, true);     // 鐘樓邊長
    const th = dim(s, 2.35, 9);           // 鐘樓牆高（要明顯高過屋脊才看得出是鐘樓）
    const sp = dim(s, 1.00, 4);           // 尖頂高
    const tz = -Math.round((nd + tw) / 2) + 1;   // 鐘樓黏在正面，交疊 1 格
    const face = tz - (tw - 1) / 2;              // 鐘樓正面那片牆的 z
    const side = (nw - 1) / 2;                   // 中殿側牆的 x

    v.box(0, 0, 0, nw + 2, 1, nd + 2, 1);        // 台基
    v.box(0, 0, tz, tw + 2, 1, tw + 2, 1);
    v.walls(0, 1, 0, nw, nh, nd, 0, 1);          // 中殿四面牆

    // 側牆的哥德長窗：windowGrid 走 tint，牆不在那裡就什麼都不會畫
    const win = { rows: 1, w: dim(s, 0.14, 1), h: dim(s, 0.55, 2), c: 3,
                  cols: dim(s, 0.30, 2), stepX: dim(s, 0.62, 3),
                  y: 1 + dim(s, 0.30, 2), axis: 'z' };
    mirrorX(v, side, (vv, dx) => windowGrid(vv, Object.assign({ x: dx, z: 0 }, win)));

    // 扶壁：貼在側牆外的一排短柱，頂端收一階。側牆有凹凸，遠看才不是一片平板
    const nb = dim(s, 0.28, 2), bd = dim(s, 0.16, 1);
    const bs = Math.max(2, Math.round((nd - 2) / nb));
    mirrorX(v, side + 1, (vv, dx) => {
      for (let i = 0; i < nb; i++) {
        const bz = Math.round(-(nd - 1) / 2 + 1 + (i + 0.5) * bs);
        vv.box(dx, 1, bz, 1, nh, bd, 1);
        vv.box(dx, 1 + nh, bz, 1, 1, Math.max(1, bd - 1), 1);
      }
    });

    v.box(0, 1 + nh, 0, nw + 2, 1, nd + 2, 1);   // 壓頂：牆與屋頂之間的深色分界
    v.gable(0, 2 + nh, 0, nw + 2, nd + 2, 2);    // 屋頂，寬多 2 格當屋簷
    v.walls(0, 1, tz, tw, th, tw, 0, 1);         // 鐘樓

    // 大門：arch 的 c 給了會先補一片牆再挖 → 一次做出石框 + 拱形洞，後面再補一片門板
    const dw = dim(s, 0.36, 3, true), dh = dim(s, 0.55, 2);
    arch(v, 0, 1, face, dw, dh, 1, 1);
    v.box(0, 1, face + 1, dw, dh + (dw - 1) / 2, 1, 5);

    /* 鐘室開口的高度先算，玫瑰窗才知道能擺多高——兩個都在同一片牆上，
       各自從「塔頂」與「門頂」量的話會撞在一起（實測撞過：鐘室的洞把玫瑰窗上半圈挖掉了）。 */
    const bw = dim(s, 0.34, 3, true), bh = dim(s, 0.50, 2);
    const by = 1 + th - bh - Math.round(bw / 2) - 1;

    // 玫瑰窗：外圈金框、裡面玻璃。畫在牆面上一律用 tint
    const rr = dim(s, 0.26, 2);
    const ry = Math.min(1 + dh + (dw - 1) / 2 + rr + dim(s, 0.16, 2), by - rr - 2);
    for (let i = -rr; i <= rr; i++) for (let j = -rr; j <= rr; j++) {
      const q = Math.hypot(i, j);
      if (q > rr + 0.35) continue;
      tint(v, i, ry + j, face, q > rr - 1 ? 4 : 3);
    }

    // 鐘室開口：arch 的牆厚是沿 z 算的，只有正背兩面能用，左右自己 carve
    mirrorZ(v, (tw - 1) / 2, (vv, dz) => arch(vv, 0, by, tz + dz, bw, bh, 1));
    mirrorX(v, (tw - 1) / 2, (vv, dx) => {
      vv.carve(dx, by, tz, 1, bh, bw);
      vv.carve(dx, by + bh, tz, 1, 1, Math.max(1, bw - 2));
    });

    v.box(0, 1 + th, tz, tw + 2, 1, tw + 2, 1);  // 塔簷
    corners4(v, (tw + 1) / 2, (tw + 1) / 2, (vv, x, z) =>       // 四角小尖塔（細、矮）
      vv.taper(x, 2 + th, tz + z, 0.9, 0.4, dim(s, 0.30, 3), 4));
    v.taper(0, 2 + th, tz, (tw + 2) / 2, 0.5, sp, 2);           // 尖頂
    const cy = 2 + th + sp, ch = dim(s, 0.30, 3);               // 十字架
    v.box(0, cy, tz, 1, ch, 1, 4);
    v.box(0, cy + Math.max(1, ch - 2), tz, 3, 1, 1, 4);

    const ns = dim(s, 0.20, 2);                                 // 台階
    stairs(v, 0, 0, face - ns, ns, dim(s, 0.55, 3, true), 'z', 1);
  }
});
```

### 4.2 圓塔

```js
customBlueprint({
  name: '磚砌鐘塔',
  pal: ['#b9a68f', '#8d8f92', '#f2efe6', '#5c4b3a'],
  lo: 2.4, hi: 11,

  gen(v, s) {
    const r = dim(s, 0.7, 3);                  // 塔身半徑
    const h = dim(s, 3.4, 9);                  // 塔身高
    v.cyl(0, 0, 0, r + 1, 2, 1);               // 石頭底座
    v.cyl(0, 2, 0, r, h, 0, 2);                // 中空塔身，牆厚 2
    arch(v, 0, 2, r, dim(s, 0.6, 3, true), dim(s, 0.9, 2), 3);       // 正面拱門（只挖，不補牆）
    windowGrid(v, { x: 0, y: 2 + dim(s, 1.2, 4), z: -r,
                    cols: 1, rows: dim(s, 0.5, 2), stepY: dim(s, 1.0, 3),
                    w: dim(s, 0.2, 1), h: dim(s, 0.4, 2), c: 2 });
    v.cyl(0, 2 + h, 0, r + 1, 1, 3);           // 一圈簷
    v.taper(0, 3 + h, 0, r + 1, 0.5, dim(s, 1.6, 5), 3, 2);          // 收尖屋頂
  }
});
```

### 4.3 有機造型（動物）

```js
customBlueprint({
  name: '小熊',
  pal: ['#8a6a4a', '#c8a06a', '#3a3330'],
  lo: 3, hi: 22,

  gen(v, s) {
    /* 有機造型用 blob 堆：半徑刻意不取整，塊數才會隨尺度連續變化
       （整數邊長的量體一階一階跳，跳幅大到怎麼掃都對不上目標塊數）。 */
    const bw = s * 0.42, bh = s * 0.5;
    blob(v, 0, bh, 0, bw, bh, bw * 0.9, 0);                             // 身體
    const hy = bh * 2 + s * 0.2, hr = s * 0.3;
    blob(v, 0, hy, -Math.round(bw * 0.3), hr, hr * 0.92, hr * 0.9, 0);  // 頭
    mirrorX(v, Math.round(hr * 0.66), (vv, dx) =>                       // 兩隻耳朵
      blob(vv, dx, hy + hr * 0.8, -Math.round(bw * 0.3), hr * 0.34, hr * 0.34, hr * 0.3, 0));
    mirrorX(v, Math.round(bw * 0.62), (vv, dx) =>                       // 兩條腿
      vv.cyl(dx, 0, Math.round(bw * 0.2), Math.max(1.4, s * 0.13),
             Math.max(2, Math.round(bh * 0.7)), 1));

    // 臉上的東西一律從外面往裡找表面：直接 set 會長出懸空孤格
    mirrorX(v, Math.round(hr * 0.4), (vv, dx) =>
      paintFrom(vv, dx, Math.round(hy + hr * 0.15), Math.round(-bw * 0.3),
                0, 0, -1, Math.ceil(hr) + 2, 2));                       // 眼睛
    paintFrom(v, 0, Math.round(hy - hr * 0.25), Math.round(-bw * 0.3),
              0, 0, -1, Math.ceil(hr) + 2, 2);                          // 鼻子
  }
});
```

## 5. 怎麼從圖片做出來

1. **先寫一份部件清單，再開始寫程式**。像不像幾乎全靠部件數——
   同樣 3000 塊，「四面牆 + 一個屋頂」看起來就是個盒子，十幾個部件才看得出是那一棟。
   照這六層去數，每一層至少挑一件做（附的小教堂範例是十四件）：

   | 層 | 例子 |
   |---|---|
   | 台基 | 地板、台階、圍欄、基座線腳 |
   | 主量體 | 牆、塔身、翼廊、柱廊 |
   | 開口 | 門、窗、拱、鐘室開口、通風口 |
   | 線腳分層 | 壓頂、腰線、簷口——**深一階的顏色橫過整棟**，一條就把牆分成上下兩段 |
   | 屋頂 | 屋頂本體、屋簷（比牆寬 2 格）、屋脊、煙囪、天窗 |
   | 頂飾與附屬 | 塔尖、小尖塔、十字架、旗桿、招牌、扶壁、雨遮 |

   每個部件一到三行，十幾件也就四十行。**不要為了省行數把部件合併掉。**
2. **每一塊都用 `dim(s, 係數, 下限)` 算尺寸，不要寫死數字**。
   量圖片上的比例（寬:高:深大約多少）換成係數；係數之間的比例就是這棟建築的長相，
   `s` 只負責整體大小。
3. **下限要給得夠**：`dim(s, 0.35, 2)` 而不是 `dim(s, 0.35, 1)`。
   下限 1 的部件在 300 塊時常常只剩一格，或整組消失。
4. **對齊要注意奇偶**。靠中線對稱的東西（屋脊、塔尖、正門）寬度取奇數（`dim` 第四參數給 `true`），
   偶數的話中心會落在兩格之間，整個偏半格。
5. **顏色分區塊給**，抓圖片的 4–6 個主色寫進 `pal`。深色留給底座與陰影面，亮色留給屋頂與招牌。
   不要一格一色做漸層——voxel 的顆粒感就是它的味道。
   **一個顏色只有一格兩格也值得留**（十字架、玫瑰窗外框、門把）：那幾格就是「認得出來」的關鍵，
   而診斷報告會盯著每個顏色在小尺寸有沒有整組消失，等於幫你守住這些小東西。
6. 交出去之前，請玩家照第 7 節開 `藍圖預覽.html` 跑一次診斷，把**報告**與**畫面截圖**一起貼回來。
   **重點是像不像**：報告只講得出塊數與結構，講不出像不像——那要看圖。
   那一頁有「下載畫面」按鈕，存下來的 PNG 直接貼給你，你就看得到自己畫出來的是什麼樣子。
   不夠像就調係數、補部件再來一次。蓋幾萬塊、蓋多久都不是問題，像才是。

## 6. `lo` / `hi` 要給多少

`lo`／`hi` 是 `s` 的掃描範圍。遊戲會在這中間找「格數最接近目標」的那個 `s`，所以：

- **`lo`**：讓建築剛好約 **300 格**的那個 `s`（玩家能設的最小值）
- **`hi`**：讓建築約 **10000 格**的那個 `s`（最大值）

**`hi` 要給得夠大。** 上萬塊正是「看得出像不像」的那一檔——
招牌、窗框、屋脊、雕花在三千塊時只是幾個色塊，上萬塊才刻得出來（體檢就是量到一萬）。
`hi` 只算到三千的話，玩家挑最大那一檔也只會拿到三千塊的那一版，
而診斷報告會直接指出來（「s 已經頂到 hi」）。

給寬一點沒關係（掃描會自己停），但**範圍沒涵蓋到目標，塊數就永遠差一截**——
診斷報告會直接告訴你「s 已經頂到 hi」。

塊數會**一階一階跳**（`round()` 與取奇數造成的），階與階之間就是誤差。
階距太大時（實測某個係數組合讓 1600 塊只挑得到 1783，差 11%），
把**跳最兇的那個維度**係數改一點點，讓它的跳點跟別的維度錯開
（實測把深度係數 1.7 改成 1.75，同一個目標從 +11% 變成 −7%）。
**不必所有維度都取奇數**——只有真的要對稱的那一個需要。

一般建築的單邊格數控制在 48 以內比較安全；橋樑、鐵塔這種細長的可以更大
（內建的金門大橋單邊 163），代價是遊戲取景會拉得很遠。

## 7. 診斷報告：怎麼拿、怎麼讀

玩家開遊戲資料夾裡的 **`藍圖預覽.html`**（不是 `index.html`，那是遊戲），
有兩條路，隨便一條都行：

（只是想馬上在遊戲裡蓋來看看的話，還有更短的一條：遊戲右上角 `🏅 成就` 底下的
**`📥 匯入建築`**，把整段貼進去按「匯入」就選得到了，而且會存著。
但**診斷報告只有預覽頁產得出來**——要修到好還是得走下面這兩條。）

- **最快：直接貼。** 把你給的那個程式碼區塊整段貼進「貼上藍圖」那個框，按「貼上並預覽」——
  馬上看得到蓋起來的樣子，診斷也一起跑好了。<code>```js</code> 圍籬與「檔名：」那行
  會自動忽略，所以**連框帶內容一起貼**就行。（貼進來的只活在那一頁，F5 就沒了。）
- **要留著就存檔**：`.js` 放進 `blueprints/`、檔名加進 `list.js`，重開那一頁就在清單裡。
  貼進來之後覺得可以了，按 **下載 .js** 就直接存成檔案（檔名就照你寫的「// 檔名：」那一行），
  不必自己再選取複製一次。`list.js` 那一步也不必自己編輯：展開 **產生 list.js**、
  按「選 blueprints 資料夾」掃一下，勾好按下載，把它覆蓋回 `blueprints/list.js` 就行。

然後 → 看它像不像 → 按 **🔍 檢查藍圖** → **複製報告** → 再按 **下載畫面** 存一張 PNG →
**報告與圖一起貼回來給你**。報告講得出塊數與結構，講不出像不像；圖才講得出來。
那一頁的建材三檔可以看 1800 塊與 9000 塊各長什麼樣、勾「只看輪廓」把草地藏起來對照參考圖
（截圖前先轉到跟參考圖同一個角度）。報告長這樣：

```
=== 積木小人 · 藍圖診斷 v1.48.0 ===
藍圖：小教堂（自訂 · gen）

塊數（目標 → 實得，偏差）
    300 →   851  +184%  s=2.20  ✔（這座最小就是這麼大，設 300 也會拿到 851 格）
   1600 →  1534    -4%  s=6.10  ✔
   3000 →  2986    +0%  s=7.79  ✔
  10000 → 10118    +1%  s=13.54  ✔
尺寸 23×46×45 格　最底層 899 格✔
配色 6 色，用到最大索引 5 ✔

300 塊時各色還在不在（跟 10000 塊比）
  ✔ pal[0] 2451→150　pal[1] 2125→300　pal[2] 5237→322　pal[3] 125→11　pal[4] 135→59　pal[5] 45→9

連通性（10118 格）：連到地面 10118 格、懸空 0 格

結論：沒有必修、沒有提醒
```

怎麼讀：

| 報告上的東西 | 意思與該怎麼做 |
|---|---|
| `✘` | **必修**。後面那行「修法」就是要改的地方 |
| `⚠` | 提醒。多半是塊數偏差超過 10%，照修法調係數或 `lo`／`hi` |
| `→ ✘ gen() 出錯：...` | 你的程式在那個尺寸丟例外了（常見：算出 0 或負數、`undefined` 進了迴圈）。照訊息修 |
| `✘ gen() 出錯：參數錯誤：…第 7 個參數 c 沒給` | 呼叫那支函式時少給參數，或那個值算成了 `NaN`。訊息已經指名是哪一支的第幾個，照 3.1／3.2 的參數表補齊就好 |
| `這座最小就是這麼大` | 不是錯。造型的最小可行尺寸比 300 塊大而已，**不要為了它去縮部件**（縮了部件會消失） |
| `s 已經頂到 hi` | `hi` 給太小，最大那一階追不上目標。照它建議的數字把 `hi` 調大 |
| `pal[n] 1234 → 0 格，整組消失` | 那個顏色的部件在小尺寸不見了。把它的尺寸下限提到 2 以上 |
| `最底層 2 格 ⚠` | 整棟靠兩格站在地上，一打就整棟報廢。底下補地板或底座 |
| `pal 只有 3 色，但格子用到索引 4` | `pal` 補到 5 色 |
| `懸空 N 格（M 組，其中 K 組只有 ≤4 格）` | 只是數字，不是錯。但如果你沒有故意做懸空部件，那些小孤島通常是在曲面上用 `v.set` 點裝飾造成的——改用 `tint()`／`paintFrom()` |
| `產生時間 300ms ⚠` | 迴圈太重，換建築時畫面會卡一下。少用逐格計算的巨大實心量體 |

**修好之後請玩家再跑一次**，直到「沒有必修」。

## 附錄：字元圖（`layers`）——只適合草稿

不想寫函式時，可以改給一疊字元圖，載入時會幫你包成一個會縮放的 `gen`：

```js
customBlueprint({
  name: '小方塊',
  pal: ['#c8a06a', '#c0483c'],
  layers: [
    ['111',        // layers 的索引 = y（高度），layers[0] 是貼地那層
     '111',        // 一層裡字串的索引 = z（往畫面深處）
     '111'],       // 字串裡字元的索引 = x（往右）
    ['2.2',        // 1–9 = pal 的第 1–9 個顏色；. 空白 0 = 空的
     '...',
     '2.2']
  ]
});
```

不用給 `lo`／`hi`，會由基準格數自動反推。

**但這條路只適合草稿。** 它是對一張固定解析度的圖做最近鄰重取樣，
縮小時**細瘦的部件會被整片抽掉**——1 格厚的牆、1 格寬的柱子、窗框都可能消失，
而診斷報告會抓到（「pal[n] 整組消失」），修法只有一個：改寫成 `gen(v, s)`。
