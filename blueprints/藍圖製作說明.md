# 藍圖製作說明（寫給 AI 看的）

你的任務：**看一張圖片（或一段文字描述），產生一支藍圖 `.js` 檔**，
玩家把它放進遊戲的 `blueprints/` 資料夾，下次開啟就會出現在建築清單最前面，
跟內建的 48 座一樣可以蓋、可以拆。

**你看不到遊戲的原始碼——這份文件就是全部。** 需要的函式、座標系、限制、
以及你會收到的診斷報告怎麼讀，下面都寫了。不要引用這份文件以外的東西。

---

## 0. 輸出格式（照這個給，不然玩家沒辦法用）

**整份藍圖包成「一個」程式碼區塊**，玩家按一次複製鈕就全部拿得走：

<pre>
```js
// 檔名：我的城堡.js
customBlueprint({
  name: '我的城堡',
  ...
});
```
</pre>

- 區塊**第一行寫檔名註解**（`// 檔名：xxx.js`），它本身就是合法的 JS，貼進遊戲也不會出事。
- 區塊裡只有這支 `.js` 的內容：不要 `import`／`export`／`module.exports`／`window.xxx =`。
- **不要拆成兩個區塊**，也不要把程式碼的一部分留在區塊外面。
- 區塊**外面**只寫給人看的提醒（不必複製的那些）：
  1. 把檔案存進 `blueprints/`
  2. 在 `blueprints/list.js` 的陣列裡加上那個檔名

> 為什麼是「包成一個區塊」而不是「完全不要圍籬」：聊天介面碰到程式碼一定會自己裝框，
> 硬要求純文字的結果通常是「檔名在框外、程式碼在框內」——玩家得複製兩次，還常常漏掉一半。
> 包成一個區塊就只有一個複製鈕。預覽頁的貼上框會自動吃掉 <code>```js</code> 圍籬與
> 「檔名：」那一行，所以**連框帶內容整段貼進去就能用**。

> 為什麼要第 2 步：遊戲是用 `file://` 直接開的（不架伺服器），
> 而 `file://` 沒辦法列出資料夾內容——`fetch` 會被 CORS 擋掉。所以檔名得自己列。

## 1. 核心觀念：造型要用函式「按尺寸重畫」，不是畫一張固定的圖

遊戲的建材數是**可挑的（遊戲面板三檔：1800／3000／9000 塊；診斷報告量的是 300／1600／3000／10000 四個尺寸，
比面板再往兩端多量一點）**，
同一座建築要能是小屋也能是大宅。
所以藍圖不是一份靜態模型，而是**一個吃尺度參數 `s` 的函式**：

```js
gen(v, s) { ... }        // 每個尺寸都用 s 重新算一次寬高，重畫一次
```

遊戲會掃 `s`，找出讓格數最接近玩家設定的那個尺寸，再呼叫你的 `gen`。
**你不用管玩家設多少塊**，只要保證「`s` 大房子就大」。

這件事非做不可的理由：造型寫死成固定解析度（例如一張字元圖）的話，
縮小時只能靠抽樣，**1 格厚的牆會被整片抽掉**——實測一棟小木屋用字元圖版縮到 300 塊時，
正面與側面兩片牆整個消失，只剩四根角柱撐著屋頂。參數化重畫不會有這個問題：
同一棟房子在 300 塊是小屋、3000 塊是大宅，門、窗、屋簷、煙囪一個都不會少。

## 2. 檔案骨架與座標系

```js
customBlueprint({
  name: '我的塔',                              // 選單上的名字（跟現有的撞名會怎樣，見下表）
  pal: ['#cfc7b8', '#8d8f92', '#c0483c'],      // 顏色表（#rrggbb），格子的 c 就是這個陣列的索引
  lo: 2.5, hi: 12,                             // s 的掃描範圍（見第 6 節）

  gen(v, s) {
    const r = dim(s, 0.4, 3);                  // 半徑跟著 s 長，下限 3
    const h = dim(s, 2.0, 6);                  // 高度跟著 s 長，下限 6
    v.cyl(0, 0, 0, r, h, 0, 2);                // 中空圓柱，牆厚 2
    v.cyl(0, h, 0, r + 1, 1, 1);               // 頂端一圈簷
    v.taper(0, h + 1, 0, r + 1, 0.5, r * 2, 2);// 收尖的屋頂
  }
});
```

| 東西 | 意義 |
|---|---|
| `x`、`z` | 水平面。**原點在中心**，可以是負的（遊戲會自己抓包圍盒置中） |
| `y` | 高度，**從 0 往上**。`y < 0` 的格子會被直接忽略 |
| `c` | `pal` 的索引（0 開始），**必須是整數**——算式算出來的要 `Math.round()` 包起來，給 2.5 這種會直接報錯（3.2 的「半徑不要取整」只講尺寸，不含 `c`）。同一格重複寫，**後寫的蓋掉先寫的** |
| `pal` | 寫 6 位的 `#rrggbb`（`#fff` 這種 3 位簡寫也認，會展開成 `#ffffff`）。**積木一律不透明**：`#rrggbbaa` 帶透明度的話，透明度會被直接丟掉——玻璃、透明杯的做法見第 5 節 |
| 小數座標 | 每一格的座標最後都會**四捨五入**（.5 進位，往 + 的方向）。所以中心、半徑都可以給小數；但寬度給**偶數**的長方體（`box`／`walls`／`carve`）中心落在兩格之間，會**往 +x／+z 多佔一格**（`w = 4`、中心 0 佔的是 −1～2） |
| `name` | 跟現有的撞名的話：貼進預覽頁、或遊戲的「匯入建築」會**自動在後面加編號**（「我的塔2」）；放成 `blueprints/` 裡的檔案則是**整份跳過**、選單上不會出現。你不知道現有的有哪些，所以名字取得具體一點（「台南赤崁樓」比「赤崁樓」不容易撞） |
| 輔助函式 | **寫在 `gen` 裡面**（`const fur = (…) => { … }`），不要寫在 `customBlueprint({ … })` 外面：檔案最外面那一層跟遊戲共用同一個全域，取到跟遊戲函式一樣的名字（例如 `dim`、`blob`）就會把遊戲自己的蓋掉 |

**正面是 `−z` 那一側**，背面在 `+z`，`+x` 是模型自己的右手邊。
臉、五官、大門、正立面、招牌、車頭一律朝 `−z`：頭往前探是 z **變小**、尾巴往後拖是 z 變大。
這件事報告的數字看不出來（塊數、配色、連通性都一樣漂亮），弄反了就是「臉長在後腦勺」，
所以每一個部件的 z 都要照這個方向擺。範例：4.1 的鐘樓黏在正面，`tz` 算出來是負的；
4.3 小熊的頭在 `z = −bw × 0.3`。

「先填實心、再挖洞」是常用手法，靠的就是後寫蓋先寫。

**不必自己保證 `y = 0` 有格子**：遊戲會把整份藍圖最低那一層貼到地面。
要在意的是「最底層有幾格」——只靠一兩格站著的話，那幾格一掉就整棟報廢。

**懸空部件是允許的**（風車扇葉、拱門下方的空洞、吊索），不會平白掉下來；
它們靠附近的積木撐著，附近被打掉就會整組掉——這是遊戲的一部分，不用避開。

**但「一大組」懸空幾乎都是錯。** 懸空件通常很小（遊戲裡現有的藍圖實測過，刻意做的懸空件最大一組也只佔整座 0.6%）；
一組佔到整座 5% 以上的，查過的都是**部件沒接上**，實測踩過三種：

- **兩件各自算高度，取整之後中間空一層**：糰子的高度另外算，在某些尺寸比球往下長的格數多一格，
  整串浮在盤子上（16%，而且只在部分尺寸出現）。
- **一格厚的殼，相鄰兩層差太多**：拉麵的碗身是一層一層一格厚的環，碗底那段曲線太陡，
  相鄰兩層半徑一下差了 3 格，上下接不起來，整個碗身跟碗腳斷開（88%）。
- **出簷只做外面一圈**：簷環跟牆面中間是空的，屋頂整片掛在空中（23%）。

所以：**上下疊的部件，上面那一件的 `y0` 一律從下面那一件的頂面算**（`y0 ＝ 下面那件的 y0 ＋ 它的高`），
不要兩件各自從地面量；一格厚的殼，相鄰兩層的半徑差超過 1 格就要往內加厚到疊得上；
出簷、陽台這種往外伸的環，要一路接回牆面。診斷報告會對這種一大組懸空示警（見第 7 節）。

## 3. 能用的函式

### 3.1 `v` 的方法（畫格子）

| 方法 | 做什麼 |
|---|---|
| `v.box(x0, y0, z0, w, h, d, c)` | 實心長方體。`x0`/`z0` 是**中心**，`y0` 是**底面所在層** |
| `v.walls(x0, y0, z0, w, h, d, c, t)` | 只留四面牆，`t` 是牆厚（預設 1）。**蓋房子的主力** |
| `v.carve(x0, y0, z0, w, h, d)` | 挖掉一塊長方體（門、窗洞、通道） |
| `v.cyl(x0, y0, z0, r, h, c, hollow)` | 站著的圓柱。`hollow` 給牆厚就只留外環。`r` 可以給小數：離中心 ≤ `r` ＋ 0.35 的格子都算 |
| `v.taper(x0, y0, z0, r0, r1, h, c, shell)` | 底半徑 `r0` 收到頂半徑 `r1`。`shell` 給牆厚就中空 |
| `v.pyramid(x0, y0, z0, b, c, step)` | 階梯方錐，底邊 `b`，每層縮 `step` 格（預設 1） |
| `v.gable(x0, y0, z0, w, d, c)` | 山牆屋頂（兩坡），實心的：一層一層的 `box`，`w` 每層縮 2 格、`d` 不變，所以**屋脊沿 z**（從正面看是三角形的山牆）、總高 ⌈w／2⌉ 層。屋脊要沿 x（正面看是一整片斜屋面，中式建築多半是這樣）就整組包進 `stampY(v, 90, …)` 轉過去 |
| `v.dome(x0, y0, z0, r, c, squash)` | 圓頂（只做殼，實心太吃積木）。`squash` < 1 是扁的 |
| `v.onion(x0, y0, z0, r, h, c)` | 洋蔥頂：先鼓出來再收尖（俄式教堂） |
| `v.eave(x0, y0, z0, w, d, c, layers)` | 屋簷：**一圈兩格厚的環**，`w`×`d` 是最外緣。`layers`（預設 2）層往上疊，每往上一層四邊各收 1 格。它**只有那一圈**，裡面是空的——要接在牆頂上，環的內緣要碰得到牆（牆比 `w` 窄超過 2 格時，中間要自己補一層，不然屋頂整片懸空，見第 2 節） |
| `v.ellipseRing(x0, y0, z0, rx, rz, h, c, thick)` | 橢圓環（競技場、圓形底座） |
| `v.line(x0, y0, z0, x1, y1, z1, c)` | 兩點之間拉一條**一格粗**的線（吊索、桁架的細斜撐）。斜著拉的時候格子只靠角碰角相連，看起來是斷成一截一截的階梯——**看得到的細棍**（吸管、竹籤、筷子、斜插的旗桿）**用 `limb`**（3.3），`r` 給 0.75 以上 |
| `v.set(x, y, z, c)` / `v.del(x, y, z)` / `v.has(x, y, z)` | 單格寫入／刪除／查詢 |

### 3.2 組合工具（直接呼叫，不用加 `v.`，但第一個參數要傳 `v`）

| 函式 | 做什麼 |
|---|---|
| `dim(s, 係數, 下限, 奇數?)` | **算尺寸都用這支**：`= Math.max(下限, Math.round(s * 係數))`，第四個給 `true` 會逼成奇數。忘了給下限是最常見的失敗 |
| `corners4(v, dx, dz, fn)` | 在 `(±dx, ±dz)` 四個角各跑一次 `fn(v, x, z)`（角塔、四根柱子） |
| `mirrorX(v, dx, fn)` / `mirrorZ(v, dz, fn)` | 左右／前後對稱：`fn(v, dx)` 跑一次、`fn(v, −dx)` 再跑一次。**`dx` 給 1 的話 `fn` 拿到的就是正負號**，斜的部件兩端都要鏡射時用它（見 3.3 `limb` 的範例） |
| `ringOf(v, n, r, fn, x0, z0, a0, span)` | 把 `n` 個東西平均排成一圈，`fn(v, x, z, 角度, 第幾個)`（柱廊、輻條）。`span`（弧度）給了就只排**一段弧**，頭尾兩個落在弧的端點上 |
| `rowOf(v, n, 間距, fn, 中心)` | **沿一條軸等距排 `n` 份**，`fn(v, 位置, 第幾個)`，以中心左右攤開；回傳整排總長。柱廊、欄杆、扶壁、衣褶、一排雕像都是它。**套兩層就是方陣** |
| `stampY(v, 幾度, fn, x0, z0)` | 把 `fn` 畫的**一整組東西**繞 y 軸轉幾度再蓋上去（斜著接出去的翼樓、放射狀排開的機庫、星形堡壘、轉過去的頭）。正的角度是 +x 轉向 +z，所以擺在 +z 的東西轉 90 度會跑到 −x |
| `arch(v, x0, y0, z0, w, h, t, c)` | 拱門。`(x0, y0, z0)` 是**開口底邊的正中間**；`w` 開口寬（自動取奇數）、`h` 直柱段高、`t` 牆厚（沿 z，以 `z0` 為中心）。開口總高 ＝ `h` ＋ (`w`−1)／2 ＋ 1 層。`c` 給了會先補一片寬 `w`＋2、高多 1 層的牆再挖，不給就只挖（用在已經有牆的立面上）。**挖穿中空的量體會看到後面的草地**，拱後面要自己補一片深色擋板 |
| `archRow(v, x0, y0, z0, n, w, h, t, pier, c)` | 一排 `n` 個拱，中間隔著寬 `pier` 的柱子。回傳整排總寬 |
| `stairs(v, x0, y0, z0, n, wide, dir, c)` | 階梯。`(x0, y0, z0)` 是**最低那一階**（1 格高），往 `dir`（`'x'`／`'-x'`／`'z'`／`'-z'`）一階一階往上爬，第 i 階高 i 格、最高那一階 `n` 格高、落在往 `dir` 走 `n`−1 格的地方。所以正面朝 −z 的大門，階梯從門前往 +z 爬：`stairs(v, 0, 0, 門的z − n, n, 寬, 'z', c)`。每階都填實到底，不會變成懸空踏面 |
| `hipRoof(v, x0, y0, z0, w, d, c)` | 四坡屋頂，實心的：一層一層的 `box`，每層四邊各收 1 格，收到寬或深剩不到 1 為止（總高 ⌈min(w, d)／2⌉ 層）。`gable` 只收寬，這支寬深一起收 |
| `tubeZ(v, x0, y0, z0, r, len, c, hollow)` | 躺著的圓柱（沿 z）：火車鍋爐、飛機機身 |
| `wheelX(v, x0, y0, z0, r, t, c, rim)` | 輪子：圓面立在 y–z 平面、厚度沿 x。`rim` 給了外圈換色 |
| `blob(v, x0, y0, z0, rx, ry, rz, c, shell)` | 橢球（動物軀幹、頭）。半徑**不要取整**，塊數才會隨尺度連續變化；中心可以是小數（會四捨五入）。**半徑 2 上下的小球會點陣化成十字形**（上下左右各凸一格尖），做耳朵、拳頭這種小圓件要圓的話，中心取整數、半徑給 2.3 以上 |
| `limb(v, { … })` | **兩點之間長出一根有粗細的東西**（斜的手臂、大腿、脖子、尾巴）。參數多，吃具名物件——見 3.3 |
| `tint(v, x, y, z, c)` | 只在「已經有積木」的格子上換色，回傳有沒有換到 |
| `paintFrom(v, x, y, z, dx, dy, dz, n, c)` | 從外面往裡掃，找到第一格實心的就換色。**`(x, y, z)` 給身體「裡面」的錨點、`(dx, dy, dz)` 指「往外」**——掃描是從 `(x + dx·n, …)` 起，一格一格走回 `(x, y, z)` |

**曲面上的裝飾（眼睛、斑紋、圓頂上的窗）一律用 `tint` 或 `paintFrom`，不要用 `v.set`**：
曲面上算出來的座標常常落在空氣裡，`v.set` 會在那裡長出一顆孤立的懸空格。

`paintFrom` 的方向最容易寫反，寫反了不會報錯——它會掃到皮下第一格，
顏色塗在看不見的地方，報告上只看得到「那個顏色的格數是對的」。臉在正面（`−z`），所以：

```js
paintFrom(v, ex, ey, headZ, 0, 0, -1, Math.ceil(hr) + 2, 2);   // 對：錨點在頭心，方向指向臉外面
paintFrom(v, ex, ey, headZ - hr - 2, 0, 0, 1, 4, 2);           // 錯：從臉前面往裡掃，塗在皮下
```

**放射狀排開的做法**（扇形的機庫、星形堡壘、風車扇葉、繞著中庭的廂房）：
照 0 度畫一份，再一份一份轉過去。以前這種東西只能自己算 `cos`／`sin` 一格一格擺：

```js
for (let i = 0; i < 5; i++)                        // 五片放射狀的翼
  stampY(v, i * 72, w => w.box(0, 0, 8, 3, 2, 9, 0));
```

**參數少給會被擋下來**：上面每一支都會在進來時驗一次參數，少給、或算出 `NaN`／`undefined`
就丟例外，診斷報告會直接寫「`v.box(x0, y0, z0, w, h, d, c)` 的第 7 個參數 `c` 沒給」。
表格裡沒有標「預設 …」「不給就 …」的參數就是**必要的**——尤其是最後那個顏色 `c`，
它是最常忘的一個。

### 3.3 參數多的六支改吃具名物件

十個位置參數排錯一個就整片跑掉，而且看不出哪裡錯，所以這六支給的是物件：

```js
// 立面窗陣列：{x,y,z} 是第一排最中間那格所在的牆面位置
windowGrid(v, { x: 0, y: 4, z: -r, cols: 3, rows: 5,
                stepX: 3, stepY: 4, w: 1, h: 2, c: 3, axis: 'x' });
// axis: 'x'（預設，窗沿 x 排在朝 ±z 的牆上）或 'z'（沿 z 排，側面兩片牆）
//   axis: 'z' 的時候鍵名照舊：stepX 就是沿 z 的間距、w 是沿 z 的窗寬；{x} 是那片側牆的 x
// 沒給的：cols／rows 預設 1、w／h 預設 1、stepX 預設 w + 1、stepY 預設 h + 1
// 走 tint，所以牆不在那裡就什麼都不會畫；回傳真的畫上去幾格（0 = 位置猜錯了）

// 斜撐格架：兩根柱子之間拉 n 段交叉斜撐（鐵塔、桁架橋）
lattice(v, { x0: -8, z0: 0, x1: 8, z1: 0, y: 0, h: 20, n: 5, c: 1 });

// 兩點之間長出一根有粗細的東西：{x,y,z} 是起點、{x1,y1,z1} 是終點、
// r 是起點半徑、r1 是終點半徑（不給就等於 r，也就是等粗的膠囊）
limb(v, { x: 4, y: 20, z: 0, x1: 7, y1: 15, z1: 2, r: 1.6, r1: 1.2, c: 0 });

// 方形收分：底面 w×d 一層一層收到頂面 w1×d1（城郭石垣、方尖碑、退縮式高樓）
// t 給了就只留四面牆（中空的方塔），不給是實心的
boxTaper(v, { x: 0, y: 0, z: 0, w: 21, d: 15, w1: 11, d1: 9, h: 6, c: 1 });

// 沿折線的薄片：立在某個平面上、有寬度也有厚度的一條帶子
// plane 決定立在哪個平面，厚度往剩下那一軸長：
//   'xy' 正面那一片（厚度沿 z）　'zy' 側面那一片（厚度沿 x）　'xz' 躺平那一片（厚度沿 y）
// pts 照 plane 的兩個字母順序給（'zy' 就是 [[z, y], …]）、at 是第三軸的中心、
// t 是厚度、w 是帶子寬度。轉折處是圓的，折線在轉角接得起來
plate(v, { plane: 'zy', at: 0, t: 2, w: 2.4, c: 3,
           pts: [[0, 10], [4, 14], [-2, 19], [3, 24]] });     // 閃電形的尾巴，立在側面

// 剖面線繞 y 軸轉一圈：[[半徑, 高度], …]，轉折點之間線性內插
// 高度是相對的：剖面最低那一點畫在 y、最高那一點那一層也有畫。不給 shell 是實心的
// shell 給了就只留外壁（中空的容器），杯底自己補一片 v.cyl
revolve(v, { x: 0, y: 0, z: 0, c: 0, shell: 1,
             prof: [[3.3, 0], [4, 3], [3.8, 9], [4.5, 10]] }); // 馬克杯：底窄、腰鼓、口外翻
```

`plate` 是**平的、彎的、薄的**那一類唯一的解：`limb` 是圓的（斜手臂、脖子、尾巴根），
`box`／`cyl`／`taper` 只能站著或沿某一軸躺著，所以閃電形的尾巴、魚鰭、翅膜、爪子、
旗子、招牌、緞帶用它們一定做不出來。實測踩過：皮卡丘的閃電尾拿 `box` 一格一格疊，
疊出來的是一片**躺在 x–z 平面的鋸齒板**（俯視圖一看就知道），而它應該立在 y 方向。
**先想清楚那一片要立在哪個平面**，再挑 `plane`。

**`w` 要比折點之間的位移小一截**（上面那個範例折點橫移 4～6，`w` 只給 2.4）。
`w` 是帶子的寬度，給得比位移還大的話**折角會被自己的寬度填平**，整條折線糊成一塊實心板。
實測踩過：一條閃電尾巴的折點只橫移 0.45 個頭寬、`w` 卻給了 0.72 個頭寬，
三段疊起來是一片看不出鋸齒的葉子形板子——`pts` 明明是對的閃電折線。
折得越密，`w` 要越小。

`revolve` 是**旋轉對稱的器物**唯一划算的做法：杯子、瓶子、碗、鐘、燈罩、花瓶、
棋子、香爐。一段一段疊 `cyl`／`taper` 的接縫是硬階，而且每加一節就多一行、
尺度一縮就對不齊。給四五個轉折點就有平滑的腰身。

`limb` 就是**斜的部件**唯一的解（同樣是因為那三支只能軸對齊）：
手臂、大腿、脖子、尾巴、翅膀根一斜就沒工具了。
半徑不要取整（塊數才會隨尺度連續變化），細到 `r: 0.5` 也不會斷成一截一截。

**兩端是圓頭，會超出端點約 `r` 格**（實測 `r` 2.2 的直棍，兩頭各多出 2 格）。接關節時這正好把接縫包住；
但要**平口**的東西（吸管口、柱頭、桌腳）就把終點往內收 `r`，或畫完把超出去那一截 `v.carve` 掉——
沒切乾淨的話會留下幾格懸空的殘塊。

**很粗、又只斜一點點的棍子會一層粗一層細**（實測 `r` 2.2、每 5 層往旁邊挪 1 格：每一層的寬在 4、5 格之間跳，
四視圖上是 S 形的波浪邊）。粗的柱狀物盡量站直用 `v.cyl`；一定要斜的話，拆成幾段 `v.cyl`、
每段中心落在整數格、一段挪一格，斜出來是整齊的階梯，比忽粗忽細好看。
器物上斜插的細棍也是它：實測兩支藍圖（超商咖啡的吸管、章魚燒的竹籤）拿 `v.line` 畫，
四視圖上是一格一格斷開的階梯；換成 `limb` 才是一根棍子。**`r` 至少給 0.75**、再跟著 `s` 長
（例如 `Math.max(0.75, s * 0.07)`）：棍子斜著跨格的時候，中心線會從四格的正中間穿過（離每一格的中心 0.71），
`r` 給 0.6、0.7 的話那四格一格都算不進去，蓋出來跟 `v.line` 一模一樣（實測幾種斜度，0.72 起才全部面貼面連起來）。

**關節就是換一支**——上臂一支、前臂一支，兩支在肘那一點共用座標：

```js
limb(v, { x: 4, y: 20, z: 0, x1: 7, y1: 15, z1: 2, r: 1.6, r1: 1.2, c: 0 });  // 肩 → 肘
limb(v, { x: 7, y: 15, z: 2, x1: 6, y1: 11, z1: 5, r: 1.2, r1: 0.9, c: 0 });  // 肘 → 手
```

**分兩段就看得出是彎的**，一根直筒到底看起來就是根柱子。左右兩邊用 `mirrorX` 包起來，
記得把終點的 `x1` 也跟著鏡射（只鏡射起點的話兩隻手臂會指向同一邊）——`dx` 給 1，拿到的就是正負號：

```js
mirrorX(v, 1, (vv, sg) => {                       // sg 是 +1（右手）與 −1（左手）
  limb(vv, { x: sg * 4, y: 20, z: 0, x1: sg * 7, y1: 15, z1: 2, r: 1.6, r1: 1.2, c: 0 });  // 肩 → 肘
  limb(vv, { x: sg * 7, y: 15, z: 2, x1: sg * 6, y1: 11, z1: 5, r: 1.2, r1: 0.9, c: 0 });  // 肘 → 手
});
```

## 4. 三個完整範例

三支都是實測過的：塊數偏差在 10% 以內，沒有部件消失、沒有孤島。
第一支是**細節密度的標準**（十四個部件），後兩支示範另外兩種造型的做法。

### 4.1 多部件建築（哥德式小教堂）

**這一支就是 `blueprints/` 裡附的那份範例**，也是「細節密度」的標準：
台基、牆、扶壁、長窗、壓頂、屋頂、鐘樓、大門、玫瑰窗、鐘室開口、小尖塔、尖頂、十字架、台階——
十四個部件，每個只有一到三行。**像不像幾乎全靠部件數，不是靠塊數。**
實測 1600／3000／10000 塊三檔偏差都在 2% 以內，六種顏色在最小尺寸也一個都沒少。

```js
customBlueprint({
  name: '小教堂',
  pal: ['#d8d0c0',   // 0 石牆（亮）
        '#9c9384',   // 1 台基、扶壁、簷（暗一階，用來分層）
        '#4a5a68',   // 2 屋頂與尖頂
        '#bfe0f2',   // 3 窗玻璃
        '#d9a441',   // 4 玫瑰窗外框、小尖塔、十字架
        '#6b4a2f'],  // 5 木門
  lo: 2.2, hi: 15.5,

  gen(v, s) {
    const nw = dim(s, 1.50, 7, true);     // 中殿寬（奇數：屋頂每層縮 2 格）
    const nd = dim(s, 2.05, 9);           // 中殿深
    const nh = dim(s, 1.25, 4);           // 中殿牆高
    const tw = dim(s, 0.85, 5, true);     // 鐘樓邊長
    const th = dim(s, 2.35, 9);           // 鐘樓牆高（要明顯高過屋脊才看得出是鐘樓）
    const sp = dim(s, 1.00, 4);           // 尖頂高
    const tz = -Math.round((nd + tw) / 2) + 1;   // 鐘樓黏在正面，交疊 1 格
    const face = tz - (tw - 1) / 2;              // 鐘樓正面那片牆的 z
    const side = (nw - 1) / 2;                   // 中殿側牆的 x

    v.box(0, 0, 0, nw + 2, 1, nd + 2, 1);        // 台基
    v.box(0, 0, tz, tw + 2, 1, tw + 2, 1);
    v.walls(0, 1, 0, nw, nh, nd, 0, 1);          // 中殿四面牆

    // 側牆的哥德長窗：windowGrid 走 tint，牆不在那裡就什麼都不會畫
    const win = { rows: 1, w: dim(s, 0.14, 1), h: dim(s, 0.55, 2), c: 3,
                  cols: dim(s, 0.30, 2), stepX: dim(s, 0.62, 3),
                  y: 1 + dim(s, 0.30, 2), axis: 'z' };
    mirrorX(v, side, (vv, dx) => windowGrid(vv, Object.assign({ x: dx, z: 0 }, win)));

    // 扶壁：貼在側牆外的一排短柱，頂端收一階。側牆有凹凸，遠看才不是一片平板
    const nb = dim(s, 0.28, 2), bd = dim(s, 0.16, 1);
    const bs = Math.max(2, Math.round((nd - 2) / nb));
    mirrorX(v, side + 1, (vv, dx) => {
      for (let i = 0; i < nb; i++) {
        const bz = Math.round(-(nd - 1) / 2 + 1 + (i + 0.5) * bs);
        vv.box(dx, 1, bz, 1, nh, bd, 1);
        vv.box(dx, 1 + nh, bz, 1, 1, Math.max(1, bd - 1), 1);
      }
    });

    v.box(0, 1 + nh, 0, nw + 2, 1, nd + 2, 1);   // 壓頂：牆與屋頂之間的深色分界
    v.gable(0, 2 + nh, 0, nw + 2, nd + 2, 2);    // 屋頂，寬多 2 格當屋簷
    v.walls(0, 1, tz, tw, th, tw, 0, 1);         // 鐘樓

    // 大門：arch 的 c 給了會先補一片牆再挖 → 一次做出石框 + 拱形洞，後面再補一片門板
    const dw = dim(s, 0.36, 3, true), dh = dim(s, 0.55, 2);
    arch(v, 0, 1, face, dw, dh, 1, 1);
    v.box(0, 1, face + 1, dw, dh + (dw - 1) / 2, 1, 5);

    /* 鐘室開口的高度先算，玫瑰窗才知道能擺多高——兩個都在同一片牆上，
       各自從「塔頂」與「門頂」量的話會撞在一起（實測撞過：鐘室的洞把玫瑰窗上半圈挖掉了）。 */
    const bw = dim(s, 0.34, 3, true), bh = dim(s, 0.50, 2);
    const by = 1 + th - bh - Math.round(bw / 2) - 1;

    // 玫瑰窗：外圈金框、裡面玻璃。畫在牆面上一律用 tint
    const rr = dim(s, 0.26, 2);
    const ry = Math.min(1 + dh + (dw - 1) / 2 + rr + dim(s, 0.16, 2), by - rr - 2);
    for (let i = -rr; i <= rr; i++) for (let j = -rr; j <= rr; j++) {
      const q = Math.hypot(i, j);
      if (q > rr + 0.35) continue;
      tint(v, i, ry + j, face, q > rr - 1 ? 4 : 3);
    }

    // 鐘室開口：arch 的牆厚是沿 z 算的，只有正背兩面能用，左右自己 carve
    mirrorZ(v, (tw - 1) / 2, (vv, dz) => arch(vv, 0, by, tz + dz, bw, bh, 1));
    mirrorX(v, (tw - 1) / 2, (vv, dx) => {
      vv.carve(dx, by, tz, 1, bh, bw);
      vv.carve(dx, by + bh, tz, 1, 1, Math.max(1, bw - 2));
    });

    v.box(0, 1 + th, tz, tw + 2, 1, tw + 2, 1);  // 塔簷
    corners4(v, (tw + 1) / 2, (tw + 1) / 2, (vv, x, z) =>       // 四角小尖塔（細、矮）
      vv.taper(x, 2 + th, tz + z, 0.9, 0.4, dim(s, 0.30, 3), 4));
    v.taper(0, 2 + th, tz, (tw + 2) / 2, 0.5, sp, 2);           // 尖頂
    const cy = 2 + th + sp, ch = dim(s, 0.30, 3);               // 十字架
    v.box(0, cy, tz, 1, ch, 1, 4);
    v.box(0, cy + Math.max(1, ch - 2), tz, 3, 1, 1, 4);

    const ns = dim(s, 0.20, 2);                                 // 台階
    stairs(v, 0, 0, face - ns, ns, dim(s, 0.55, 3, true), 'z', 1);
  }
});
```

customBlueprint({

### 4.3 有機造型（動物）

```js
customBlueprint({
  name: '小熊',
  pal: ['#8a6a4a', '#c8a06a', '#3a3330'],
  lo: 3, hi: 22,

  gen(v, s) {
    /* 有機造型用 blob 堆：半徑刻意不取整，塊數才會隨尺度連續變化
       （整數邊長的量體一階一階跳，跳幅大到怎麼掃都對不上目標塊數）。
       斜的部件（彎的手臂、大腿、尾巴）用 limb，見 3.3。 */
    const bw = s * 0.42, bh = s * 0.5;
    blob(v, 0, bh, 0, bw, bh, bw * 0.9, 0);                             // 身體
    const hy = bh * 2 + s * 0.2, hr = s * 0.3;
    blob(v, 0, hy, -Math.round(bw * 0.3), hr, hr * 0.92, hr * 0.9, 0);  // 頭
    mirrorX(v, Math.round(hr * 0.66), (vv, dx) =>                       // 兩隻耳朵
      blob(vv, dx, hy + hr * 0.8, -Math.round(bw * 0.3), hr * 0.34, hr * 0.34, hr * 0.3, 0));
    mirrorX(v, Math.round(bw * 0.62), (vv, dx) =>                       // 兩條腿
      vv.cyl(dx, 0, Math.round(bw * 0.2), Math.max(1.4, s * 0.13),
             Math.max(2, Math.round(bh * 0.7)), 1));

    // 臉上的東西一律從外面往裡找表面：直接 set 會長出懸空孤格
    mirrorX(v, Math.round(hr * 0.4), (vv, dx) =>
      paintFrom(vv, dx, Math.round(hy + hr * 0.15), Math.round(-bw * 0.3),
                0, 0, -1, Math.ceil(hr) + 2, 2));                       // 眼睛
    paintFrom(v, 0, Math.round(hy - hr * 0.25), Math.round(-bw * 0.3),
              0, 0, -1, Math.ceil(hr) + 2, 2);                          // 鼻子
  }
});
```

## 5. 怎麼從圖片做出來

**開工前先寫下三句話，而且寫進 `.js` 開頭的註解裡**（`// 檔名：` 那行的下面）：

```js
// 檔名：馬克杯.js
// 正面：直筒，右邊一個 C 形握把伸出去
// 側面：杯口比杯底寬一點，握把的厚度只有杯身的一半
// 三樣識別物：C 形握把、杯口外翻的厚邊、杯身中央那條橫色帶
// 部件：杯身(revolve) 杯底 握把(plate) 杯口厚邊 色帶(tint) 杯墊 …
```

1. 從**正面**看，它的輪廓是什麼形狀？（正面 ＝ `−z` 那一面，見第 2 節）
2. 從**側面**看是什麼形狀？
3. 哪**三樣東西**讓人一眼認出它？（火炬與七芒冠、法老頭巾、層層屋簷與金鯱、橘紅色主塔與下垂的主纜）

**為什麼要寫進註解而不是只想在心裡**：這三句話等一下要拿來驗收——第 7 節的診斷報告
會附三張字元輪廓圖（正面／側面／俯視），對著這三句話一條一條比，比得上就是像，
比不上就知道要補哪裡。沒寫下來的話，回頭看報告只會覺得「好像還好」，改不出方向。
寫進註解還有兩個好處：改下一版時看得到自己上一版打算做什麼（不會愈改愈偏），
而那張部件清單就是「有沒有漏做」的對帳單。註解是合法的 JS，留在檔案裡不會出事。

1. **先寫一份部件清單，再開始寫程式**。像不像幾乎全靠部件數——
   同樣 3000 塊，「四面牆 + 一個屋頂」看起來就是個盒子，十幾個部件才看得出是那一棟。
   照這六層去數，每一層至少挑一件做（附的小教堂範例是十四件）：

   | 層 | 例子 |
   |---|---|
   | 台基 | 地板、台階、圍欄、基座線腳 |
   | 主量體 | 牆、塔身、翼廊、柱廊 |
   | 開口 | 門、窗、拱、鐘室開口、通風口 |
   | 線腳分層 | 壓頂、腰線、簷口——**深一階的顏色橫過整棟**，一條就把牆分成上下兩段 |
   | 屋頂 | 屋頂本體、屋簷（比牆寬 2 格）、屋脊、煙囪、天窗 |
   | 頂飾與附屬 | 塔尖、小尖塔、十字架、旗桿、招牌、扶壁、雨遮 |

   每個部件一到三行，十幾件也就四十行。**不要為了省行數把部件合併掉。**
   幾件常見的直接有工具：一整排等距的柱子、欄杆、扶壁用 `rowOf`；下寬上窄的石垣、
   台基、退縮式高樓用 `boxTaper`；斜著接出去的翼樓、放射狀排開的廂房用 `stampY`。

   **人物、動物、神像走另外一套六層。** 上面那套是建築的，人像照它去數會把部件花在
   「開口」與「頂飾」上（附的八卦山大佛就是：蓮座上開了一圈圓窗、座前加了一座香爐，
   而佛身、雙臂、佛首全是軸對齊的方塊疊起來的）。人與動物照這六層數：

   | 層 | 例子 |
   |---|---|
   | 著地 | 腳掌與著地的那一面；神像才有的台座、蓮座、岩盤。**動物、角色就是腳掌，不是另外加一塊台基**（見下面〈不要無故加台基〉） |
   | 姿勢 | 站／坐／伏臥、重心在哪隻腳、頭轉向哪邊、手臂舉起還是垂下——**這是第一眼認人的東西** |
   | 軀幹 | 胸、腰、臀的粗細變化。一根等粗的柱子怎麼看都不是人 |
   | 四肢與關節 | 上臂／前臂、大腿／小腿**各分兩段**，肩、肘、膝各換一次方向——用 `limb`（3.3） |
   | 頭與五官 | 頭的量體、下巴、髮／冠／頭巾。五官在三千塊只有一兩格，一律用 `tint`／`paintFrom` 點 |
   | 衣物與識別物 | 衣褶、腰帶、披風，加上開工前寫的那**三樣一眼認出它的東西** |

   **器物、食物、玩具、包裝走第三套六層。** 這一類的量體通常只有一兩件（一個杯子、
   一塊咖哩、一個座布團），像不像幾乎全靠**表面**與**附件**——照建築那套去數的話，
   部件會花在「屋頂」與「頂飾」上，做出來是一個放在台基上的圓柱體：

   | 層 | 例子 |
   |---|---|
   | 主量體與剖面 | 杯身、碗、瓶、方塊、抱枕——旋轉對稱的一律用 `revolve`（3.3），別疊 `cyl` |
   | 口緣與開口 | 杯口外翻的厚邊、瓶頸、碗沿、盒蓋的縫、開口處的內壁 |
   | 附件 | 握把、吸管、蓋子、湯匙、綁帶、標籤環——薄而彎的用 `plate`、斜插的細棍（吸管、竹籤、筷子）用 `limb`（3.3） |
   | 內容物 | 杯裡的液面、碗裡的麵、盒裡露出的一角。**液面高度差一點就換一種東西** |
   | 表面紋理與分區 | 橫色帶、格線、烙印、雕花、光澤的亮面（亮一階的顏色貼在朝 `−z` 的那面） |
   | 文字與圖案 | 招牌字、商標、笑臉、圖騰。一格兩格也要留，那就是「認得出來」的關鍵 |

   **不要無故加台基。** 台基只在建築那一套裡；角色、動物、器物**站在地上就好**
   （遊戲會自動把最低那層貼到地面，見第 2 節）。實測踩過：一隻皮卡丘腳下多了一圈
   綠色圓台基，沒有人要求，是照建築那套六層數出來的。要加底物只有一個理由——
   它本來就站在什麼東西上面（座布團、黏鼠板、盤子、杯墊），而那是「內容物／底物」，
   不是台基。

   **比例先定頭，其餘一律寫成頭的倍數**——人與動物第一眼看的是頭身比，差一成就換一個人：

   ```js
   const hd   = dim(s, 0.55, 3);        // 頭高：整尊唯一的錨
   const body = Math.round(hd * 6.5);   // 站姿的人約 7～8 頭身（含頭），坐佛約 4～5
   const arm  = Math.round(hd * 3);     // 手臂約 3 個頭長，大腿加小腿約 4 個
   ```

   上面是拿 `box` 疊的寫法（要整數）。**用 `blob`／`limb` 堆的動物與角色，錨不必取整**
   （`const R = s * 0.5`，其餘寫成 `R` 的倍數），跟「半徑不要取整」是同一個道理，塊數才會連續。

   各部位各給一組係數的下場是：`s` 一縮，頭四捨五入到 3 格、身體還有 9 格，整尊變成另一種比例。
   實測內建的自由女神就是 **3.5 頭身**（真實比例約 8）。3.5 不一定是錯的——頭再小就刻不出五官——
   但這個數字**現在沒有任何一條檢查看得到**，只有第 7 節那三張輪廓圖照得出來。
   要縮就整尊一起縮，不要只有頭走鐘。
2. **每一塊都用 `dim(s, 係數, 下限)` 算尺寸，不要寫死數字**。
   量圖片上的比例（寬:高:深大約多少）換成係數；係數之間的比例就是這棟建築的長相，
   `s` 只負責整體大小。
3. **下限要給得夠**：`dim(s, 0.35, 2)` 而不是 `dim(s, 0.35, 1)`。
   下限 1 的部件在 300 塊時常常只剩一格，或整組消失。
4. **對齊要注意奇偶**。靠中線對稱的東西（屋脊、塔尖、正門）寬度取奇數（`dim` 第四參數給 `true`），
   偶數的話中心會落在兩格之間，整個偏半格。
5. **顏色分區塊給**，抓圖片的 5–7 個主色寫進 `pal`。深色留給底座與陰影面，亮色留給屋頂與招牌。
   不要一格一色做漸層——voxel 的顆粒感就是它的味道。
   **一個顏色只有一格兩格也值得留**（十字架、玫瑰窗外框、門把）：那幾格就是「認得出來」的關鍵，
   而診斷報告會盯著每個顏色在小尺寸有沒有整組消失，等於幫你守住這些小東西。

   **遊戲的光照會把淺色洗得更白**，挑色時要往暗、往飽和調一點。下面講的「亮度」你可以自己從色碼算：
   **亮度 ＝（R、G、B 三個分量裡最大的 ＋ 最小的）÷ 2 ÷ 255**（就是 HSL 的 L）。例如 `#d9c9a3` 是
   (217 + 163) ÷ 2 ÷ 255 ≈ 0.75，`#cfa868` 是 (207 + 104) ÷ 2 ÷ 255 ≈ 0.61。實測：

   - `#d9c9a3` 這種米色在遊戲裡**看起來幾乎是白的**，換成 `#cfa868` 才看得出是金黃的石灰岩；
     一個布丁的卡士達用 `#f3cf6b`（≈ 0.69）畫出來是淡卡其，`#f4bd48`（≈ 0.62）才是蛋黃色。
   - 實測過的一批藍圖裡，有好幾支淺色（亮度 > 0.75）佔了整座一半以上，蓋出來是一團分不出面的白。

   規則是：

   - **有顏色的材質（米色、木頭、磚、石、金、食物），大面積的主色亮度壓在 0.65 以下。**
   - **主色（佔最多格的那個顏色）不超過整座的 55%**：同一種材質分兩三階（亮面、本色、陰影），面跟面才分得開。
   - **白的東西照實物，但要配一階灰、一階陰影色**：白宮、白瓷碗、鮮奶油本來就是白的，不要改成別的顏色；
     可是大面積不要用純白（`#ffffff`、`#f5f5f7`），用略帶暖或冷的淺灰白（亮度 0.8～0.88），
     再配一階明顯暗的陰影色（亮度 0.6～0.7）放在簷下、內凹面、底部、背光那幾面。
   - 每個顏色實際佔多少你在寫程式時算不出來——**診斷報告的「配色」那一行會印出 3000 塊那一階每個顏色
     佔幾成、亮度多少**（見第 7 節），拿那一行對這三條。
   - **整隻是黑色（深色）的東西**，深色一樣會被光照洗灰：三階都壓在亮度 0.08～0.2、彼此差不要超過 0.06，
     **用固定雜湊撒在同一個部件上**，不要一個部件一階（盲測踩過：一隻黑熊亮的那一階給 0.25，受光面看起來是灰褐色；
     四肢整段用暗一階，正面看像穿了黑褲子）。深色的臉上點五官，眼睛、鼻頭要用亮一兩階的顏色才看得見。
   - **積木都不透明**。透明的杯子、玻璃窗：畫看得到的內容物（飲料、窗後的暗色），只有空的那一段
     （液面以上、杯口捲邊）用很淺的灰藍，再加一條亮一階的直條當反光——盲測做珍珠奶茶就是這樣，看得出是透明杯。
   - **認得出它的顏色一定要進 `pal`**：開工前寫的三樣識別物裡如果有顏色，那就是最不能省的一色。
     實測踩過：一支中正紀念堂的 6 色全是灰（沒有那片藍屋頂），兩支曜變天目碗只有黑到白的灰階（沒有藍色光斑）——
     造型都對，就是認不出來。
   - **石材、磚牆的質感用固定雜湊挑兩三階深淺**（每一塊各自風化），不要一層一色的條紋。
     只塗在看得到的那一面就好（`tint` 只換已經有積木的格子）：

     ```js
     // 固定雜湊：同一格每次算出來都一樣（不要用 Math.random——每產一次顏色就不一樣）
     const H = (x, y, z) => (((x * 73856093) ^ (y * 19349663) ^ (z * 83492791)) >>> 0) % 100;
     // 正面那片牆（z ＝ wallZ、x 從 −half 到 half、高 wallH）蓋好之後，挑兩階暗色（pal[6]、pal[7]）
     for (let y = 1; y <= wallH; y++)
       for (let x = -half; x <= half; x++) {
         const h = H(x, y, wallZ);
         if (h < 25) tint(v, x, y, wallZ, 6);
         else if (h < 35) tint(v, x, y, wallZ, 7);
       }
     ```

     **只塗看得到的那幾面，不要蓋完再把整個包圍盒逐格掃一遍重上色**：遊戲為了找出最接近目標塊數的尺寸，
     一輪會呼叫 `gen` 約六十次，整份重掃的成本跟著乘六十倍（實測一座金字塔 9000 塊那一檔
     整份重掃要 315ms、改成一邊蓋一邊挑色是 84ms；超過 250ms 換建築時畫面會卡）。
6. 交出去之前，請玩家照第 7 節開 `藍圖預覽.html` 跑一次診斷，把**報告**與**畫面截圖**一起貼回來。
   **重點是像不像**：報告裡那三張輪廓圖講得出輪廓與比例（拿開工前寫的三句話去對），
   但顏色、材質、哪一塊接著哪一塊還是只有圖看得出來。
   那一頁有「下載四視圖」按鈕，存下來的 PNG 是正面／右側／俯視／45° 四格拼成的一張，
   每一格角上寫著是哪一面。直接貼給你，你就看得到自己畫出來的是什麼樣子、正面到底對不對。
   不夠像就調係數、補部件再來一次。蓋幾萬塊、蓋多久都不是問題，像才是。

## 6. `lo` / `hi` 要給多少

`lo`／`hi` 是 `s` 的掃描範圍。遊戲會在這中間找「格數最接近目標」的那個 `s`，所以：

- **`lo`**：讓建築剛好約 **300 格**的那個 `s`（玩家能設的最小值）
- **`hi`**：讓建築約 **10000 格**的那個 `s`（最大值）

**`hi` 要給得夠大。** 上萬塊正是「看得出像不像」的那一檔——
招牌、窗框、屋脊、雕花在三千塊時只是幾個色塊，上萬塊才刻得出來（體檢就是量到一萬）。
`hi` 只算到三千的話，玩家挑最大那一檔也只會拿到三千塊的那一版，
而診斷報告會直接指出來（「s 已經頂到 hi」）。

給寬一點沒關係（掃描會自己停），但**範圍沒涵蓋到目標，塊數就永遠差一截**——
診斷報告會直接告訴你「s 已經頂到 hi」。

**`hi` 的估法：至少給 3000 塊那個 `s` 的 2.2 倍。** 實測過的一批藍圖，從 3000 塊長到 10000 塊
`s` 要放大 1.5～2.1 倍，哪一支落在哪裡事前猜不準，所以一律給到 2.2 倍。
其中有 4 支 `hi` 不夠、最大那一檔長不上去，它們的 `hi` 都只給到 3000 塊那個 `s` 的 1.1～1.5 倍
（一個馬克杯 9000 塊那一檔只長到 3745）。
**第一版還沒有報告**，3000 塊的 `s` 只能自己估：照你的尺寸公式粗算一下格數（牆、殼大約是面積、
實心量體大約是體積），估不準就把 `hi` 給大一點；報告回來之後，「3000 → … s=」那一行就是真正的值，
再照 2.2 倍改。

**改了部件，每一檔挑到的 `s` 都會跟著變**：讓塊數變多的改動（加厚、加部件）會讓同一個檔位挑到更小的 `s`。
盲測踩過：照上一版報告的 `s` 算好城基高度要放得下拱門，加深出簷之後 3000 那一檔的 `s` 從 6.58 掉到 5.56，
拱門又不見了。要確定某個部件在某一檔出現，拿**新的**報告那一行的 `s=` 再算一次。

塊數會**一階一階跳**（`round()` 與取奇數造成的），階與階之間就是誤差。
階距太大時（實測某個係數組合讓 1600 塊只挑得到 1783，差 11%），
把**跳最兇的那個維度**係數改一點點，讓它的跳點跟別的維度錯開
（實測把深度係數 1.7 改成 1.75，同一個目標從 +11% 變成 −7%）。
**不必所有維度都取奇數**——只有真的要對稱的那一個需要。

一般建築的單邊格數控制在 48 以內比較安全；橋樑、鐵塔這種細長的可以更大
（內建的金門大橋單邊 163），代價是遊戲取景會拉得很遠。

## 7. 診斷報告：怎麼拿、怎麼讀

玩家開遊戲資料夾裡的 **`藍圖預覽.html`**（不是 `index.html`，那是遊戲），
有兩條路，隨便一條都行：

（只是想馬上在遊戲裡蓋來看看的話，還有更短的一條：遊戲右上角 `🏅 成就` 底下的
**`📥 匯入建築`**，把整段貼進去按「匯入」就選得到了，而且會存著。
但**診斷報告只有預覽頁產得出來**——要修到好還是得走下面這兩條。）

- **最快：直接貼。** 把你給的那個程式碼區塊整段貼進「貼上藍圖」那個框，按「貼上並預覽」——
  馬上看得到蓋起來的樣子，診斷也一起跑好了。<code>```js</code> 圍籬與「檔名：」那行
  會自動忽略，所以**連框帶內容一起貼**就行。（貼進來的只活在那一頁，F5 就沒了。）
- **要留著就存檔**：`.js` 放進 `blueprints/`、檔名加進 `list.js`，重開那一頁就在清單裡。
  貼進來之後覺得可以了，按 **下載 .js** 就直接存成檔案（檔名就照你寫的「// 檔名：」那一行），
  不必自己再選取複製一次。`list.js` 那一步也不必自己編輯：展開 **產生 list.js**、
  按「選 blueprints 資料夾」掃一下，勾好按下載，把它覆蓋回 `blueprints/list.js` 就行。

然後 → 看它像不像 → 按 **🔍 檢查藍圖** → **複製報告** → 再按 **下載四視圖** 存一張 PNG →
**報告與圖一起貼回來給你**。
報告裡的三張輪廓圖講得出形狀與比例，
但顏色、材質、哪一塊接著哪一塊只有圖看得出來，所以兩個都要。
那張 PNG 是**正面（−z）／右側（+x）／俯視／45°** 四格拼成的，角度是固定的、角上有標，
不必自己轉到某個角度再截圖——**正面那一格就是驗「臉／大門有沒有朝對邊」的地方**。

**兩種圖不是同一個尺寸、方向也不一樣**（盲測時三個 AI 都在這裡卡過）：

| | PNG 四視圖 | 報告裡的字元輪廓圖 |
|---|---|---|
| 畫的是哪一檔 | 預覽頁**當下選的那一檔**（預設 3000；要看大的，請玩家切到 9000 再下載一次）。報告最後那一行的塊數就是這一張 | 10000 那一階 |
| ① 正面 | **站在正面看**，`+x`（模型自己的右手）在畫面**左邊**——跟面對一個人一樣 | `+x` 印在**右邊**（站在背後看的左右） |
| ③ 俯視 | 正面（`−z`）在畫面**下方**、`+x` 在左邊 | 正面在**上方**、`+x` 在右邊（兩張差 180°） |

所以「上萬塊才刻得出來」的小細節，3000 那張 PNG 上看不到是正常的；要確認就請玩家多給一張 9000 的。
**像不像以 PNG 為準**：盲測時三座藍圖三輪報告都是全 ✔、零 ⚠，所有真正的問題（屋頂吃掉牆、吸管忽粗忽細、
黑熊看起來像穿褲子）都只在 PNG 上看得到。

**拿到四視圖，第一件事看 ① 正面那一格**：看得到臉、大門、正立面，才往下比像不像；
看到的是後腦勺、背立面，就是整份的前後做反了（報告的數字一個都不會變，只有這一格看得出來）。
修法是把 `gen` 的內容整個包進 `stampY` 轉 180°，裡面一字不改：

```js
gen(v0, s) {
  stampY(v0, 180, v => {
    // …原本 gen 裡的內容，原封不動…
  });
}
```

**不要只把 z 取負號**：那是鏡射，左右會對調（拿在右手的東西跑到左手）。轉 180° 是 x、z 一起換號，
左右才對。實測踩過：一支應援兔兔的眼睛、嘴、肚皮全畫在 +z，正面那一格只看得到後腦勺。

包一層 `stampY` 的代價是**產生時間變兩倍多**（它要先在另一塊畫布上整份畫一遍再轉過來；
那支兔兔 9000 塊那一檔 146ms → 337ms）。報告因此出現「產生時間 ⚠」的話，就改成自己把每個座標的
x、z 一起換號（`x` → `-x`、`z` → `-z`），那樣沒有額外成本。
那一頁的建材三檔可以看 1800 塊與 9000 塊各長什麼樣、勾「只看輪廓」把草地藏起來對照參考圖。

| `⚠` | 提醒。多半是塊數偏差超過 10%，照修法調係數或 `lo`／`hi` |
| `→ ✘ gen() 出錯：...` | 你的程式在那個尺寸丟例外了（常見：算出 0 或負數、`undefined` 進了迴圈）。照訊息修 |
| `✘ gen() 出錯：參數錯誤：…第 7 個參數 c 沒給` | 呼叫那支函式時少給參數，或那個值算成了 `NaN`。訊息已經指名是哪一支的第幾個，照 3.1／3.2 的參數表補齊就好 |
| `這座最小就是這麼大` | 不是錯。造型的最小可行尺寸比 300 塊大而已，**不要為了它去縮部件**（縮了部件會消失） |
| `s 已經頂到 hi` | `hi` 給太小，最大那一階追不上目標。照它建議的數字把 `hi` 調大 |
| `pal[n] 1234 → 0 格，整組消失` | 那個顏色的部件在小尺寸不見了。把它的尺寸下限提到 2 以上 |
| `最底層 2 格 ⚠` | 整棟靠兩格站在地上，一打就整棟報廢。底下補地板或底座 |
| `pal 只有 3 色，但格子用到索引 4` | `pal` 補到 5 色 |
| `配色比例` 那三行 | 3000 塊那一階每個顏色佔幾成、亮度多少——**只算露在外面看得到的格子**（裝滿的杯子、實心的身體，裡面看不到的不算）。不會有 ✘ 也不會有 ⚠，拿來對第 5 節的配色規則：有顏色的材質主色亮度 ≤ 0.65、主色佔 ≤ 55%、淺色別超過一半。主色或淺色佔一半以上時會多一句提示——本來就白的東西（白宮、白瓷）照實物，補一階灰與陰影色就好，不要硬塗成別的顏色 |
| `懸空 N 格（M 組，其中 K 組只有 ≤4 格）` | 只是數字，不是錯。但如果你沒有故意做懸空部件，那些小孤島通常是兩種：在曲面上用 `v.set` 點裝飾（改用 `tint()`／`paintFrom()`），或 `carve` 切掉一截之後留下的殘塊（例如 `limb` 的圓頭超出終點，切平時沒切乾淨） |
| `⚠ N 塊那一檔有一組 M 格連不到地面（佔整座 x%…）` | **一大組懸空，這是錯**（佔 5% 以上才會出現）。多半是接縫差一格，見第 2 節：上面那件的 `y0` 從下面那件的頂面算，或往下多疊一層壓住接縫。常常只在某幾個尺寸才出現，所以報告四個尺寸都量 |
| `產生時間 300ms ⚠` | 迴圈太重，換建築時畫面會卡一下。少用逐格計算的巨大實心量體 |
| `輪廓` 那三張圖 | 不會有 ✘ 也不會有 ⚠——像不像沒有門檻，只有你拿參考圖對照才判斷得出來。**這是報告裡唯一講得出「像不像」的東西**：對著開工前寫的三句話比輪廓、比各部位的長短粗細（人物與動物先比頭身比），對不上就調係數、補部件 |
| 輪廓圖上某個部件根本看不到 | 那個部件太小、被別的量體吃掉了（後寫蓋先寫），或位置算錯畫到別的地方去了。不是降採樣的問題——降採樣取的是「這一格區塊有沒有積木」，1 格粗的旗桿照樣看得到 |

## 附錄：字元圖（`layers`）——只適合草稿

不想寫函式時，可以改給一疊字元圖，載入時會幫你包成一個會縮放的 `gen`：

```js
customBlueprint({
  name: '小方塊',
  pal: ['#c8a06a', '#c0483c'],
  layers: [
    ['111',        // layers 的索引 = y（高度），layers[0] 是貼地那層
     '111',        // 一層裡字串的索引 = z（往畫面深處）
     '111'],       // 字串裡字元的索引 = x（往右）
    ['2.2',        // 1–9 = pal 的第 1–9 個顏色；. 空白 0 = 空的
     '...',
     '2.2']
  ]
});
```

不用給 `lo`／`hi`，會由基準格數自動反推。

**但這條路只適合草稿。** 它是對一張固定解析度的圖做最近鄰重取樣，
縮小時**細瘦的部件會被整片抽掉**——1 格厚的牆、1 格寬的柱子、窗框都可能消失，
而診斷報告會抓到（「pal[n] 整組消失」），修法只有一個：改寫成 `gen(v, s)`。
