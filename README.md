# 積木小人 · 世界地標工地　`v1.24.0`

一進來就有一座蓋好的世界地標。你把它砸爛，小人們才會從滿地的碎料裡
一塊一塊搬出來，慢慢蓋出下一座。被打到的地方才會壞，沒波及的地方原封不動。

**雙擊 `index.html` 就能玩**，不用開 server、不用連網路。

## 遊玩循環

```
開場：一座蓋好的建築（完工）
  ↓ 你動手砸
拆除中：小人退到旁邊看，不會偷偷幫你修
  ↓ 拆到只剩 25% 以下
剩下的自己垮掉 → 隨機開下一座地標
  ↓ 推土機進場
整地中：推土機把堆起來的碎料推出工地範圍，推完小人才開工
  ↓ 小人搬運施工
完工 → 繞圈慶祝 → 回到開頭
```

還沒蓋完就被砸的話，小人**會**把洞補回去——那是修補，跟拆除是兩回事。

不想等小人搬完，左下面板有 **⚡ 立刻建成**：整座直接長出來，phase 跳到完工。
它走的是開場那條 `completeNow()`，所以**一毛人力費都不加**（人力費是 `step()` 裡
隨施工時間累積的），按不出「百萬工程」那種花錢成就；施工計時也歸零，
順帶擋掉「奇蹟工程」（那是比速度的）。蓋過哪些地標、幾塊的大工程照記。
已經燒掉的工錢不會被抹掉——歸零的話 HUD 的「本次人力」會跟「累計」對不上。

## 藍圖與建材數

36 座地標各是一個吃尺度參數 `s` 的 voxel 產生器。積木數不是寫死的：
`fitScale()` 拿實際格數掃 `s`，找最接近目標的那個尺寸——不是套公式估，
因為挖洞跟取整會讓「塊數對 s」上下跳，估出來的差很多。

**預設 3000 塊**（面板可調 300–3000）。這個預設值讓「每座的實際塊數要貼齊目標」
變重要：人力費算的是工時，塊數少的那座就明顯便宜、也明顯矮小。
以前設 3000 時實得 1806～3205 塊（差 1.8 倍），現在 36 座的偏差都在 **5% 以內**。

三件事湊出這個結果：

- **細掃步長改成 `coarse/20`**。造型參數大多經過 `round()`／`|1` 取整，塊數是一階一階跳的，
  階與階的邊界很窄；原本 `coarse/6` 會整階跨過去，挑到偏差 7% 的那一階
  （京都五重塔挑到 3205，同一段裡其實有 2978）。代價是掃描次數翻倍，
  最慢的那幾座（雪梨歌劇院、農神五號、羅馬競技場）換建築時要 50～60 ms，
  還在 e2e 的 250 ms 預算內。
- **三座長不到 3000 的放寬尺度**：艾菲爾鐵塔（頂到上限只有 1806）、金門大橋（2243）、
  羅浮宮金字塔（2833）。鐵塔另外把下半段的塔腳加粗到 2×2——真的鐵塔下面是四座巨大的桁架墩，
  整根都一格粗的話尺度一放大就整座空掉。**斜撐沒有加密**：試過分段從 `s/7` 改成 `s/4.6`，
  3000 塊時下半段的 X 撐整片黏成實心，底下四道大拱全被埋掉，遠看變階梯金字塔。
  要塊數就讓它長高，不是把面填滿。
- **兩座被「奇數寬度」卡住的改瘦**：倫敦大笨鐘與帝國大廈的塔身寬度只能是奇數
  （鐘面／退縮靠 `(w−1)/2` 貼在牆面上，偶數會浮出一格），所以 `w` 一跳就是 2 格，
  塊數跟著跳一大階——大笨鐘的相鄰兩階是 2687 和 3764，目標 3000 永遠差 10%。
  寬度係數改小（0.2→0.17、0.5→0.42）讓同一個 `w` 撐得更高，階距就縮小了，
  順帶更接近真的比例（大笨鐘高寬比 8:1）。

順手修掉一個藍圖 bug：**金門大橋在奇數跨距時整座沒有吊索**。跨距 `L` 是奇數時
`−L/2` 是 .5，整條橋的 x 都變半格，吊索那行的 `x % 3 === 0` 永遠不成立
（`s=56` 只有 1636 塊，比小一號的 `s=50` 的 1847 還少）。改成用整數半跨跑迴圈。
橋面也從 3 格加寬到 5 格鋪滿兩道主纜之間——本來兩側的吊索是吊在橋面外的空氣裡。

把底部打掉，上面失去支撐的部分會跟著垮。判定方式是從地面那一層做連通性搜尋，
連不到地面的就鬆脫，而且越高的越晚掉，垮下來才有由下往上的層次。

藍圖本身就懸空的部件（摩天輪車廂、大橋吊索、101 疊起來的八節）不連到地面，
但也不是無敵——它們記著「附近撐著自己的那些格子」，那些被打掉四分之三以上就整組掉，
而且會一路連鎖下去。

## 整地

換下一座之前，上一輪的碎料還躺在工地上，而且**不是平均鋪開的**——只拿槌子敲的話，
碎料會全堆在挨打的那一區。所以會開三台推土機進來，各自找一坨最密的碎料，
繞到那坨的內側朝外推，把它推出工地範圍，再去找下一坨。
沒有值得推的堆了（或六秒半到）小人才進場——不會在還沒整平的地上開工。

車速是**固定的**：空車 9.5，推著碎料時 6.5——小人走路是 6.8，推土機本來就該是慢的。
不管工地半徑是 8 還是 69 都一樣，不會為了趕完而飆起來。

開推之前會先在起點怠速 1.3 秒。剛換建築的那一刻，上一座還有四分之一是整片炸開飛在半空的；
不等它們落地就開推，它們會落在鏟子後面已經推過的地上。

推的做法是：鏟面**前方** 7 單位內、鏟子寬度內的碎料，每幀跟著車子走同樣的位移——
整坨維持相對位置往前，這才像被推著。推到工地邊緣再往外 9 單位才收手，
不然機器停下時那一坨的尾巴還留在工地裡。

那一坨會越推越密（車子一直往前收新的進來），所以要讓它往前、往兩側散開，
但**散開的速度必須比車子慢**。直接套碎塊落地用的 `separate` 一幀能推開 4.7 單位，
碎料會瞬間被彈出鏟子範圍——畫面上是機器周圍一圈空地、鏟子前面什麼都沒有。
所以另外寫了力道打折、位移給上限的 `nudgeApart`。

## 取景

換一座建築就重新取景一次：把建築當成一顆球，距離 = 球半徑 ÷ sin(半視角)。

**上下與左右要分開算。** 上下用球半徑，左右另外用真正的水平半徑再算一次，取比較遠的那個：

- 左右完全不算（只看垂直 fov）→ 直式手機畫面高瘦，36 座地標有 24 座被切掉，金門大橋溢出六成。
- 兩邊都用球半徑 → 球半徑被**高度**撐大，又高又細的艾菲爾鐵塔會被自己的高度推到天邊，
  在手機上縮成一根牙籤。

留白係數 `FIT_MARGIN` 是量出來的，不是喬出來的：36 座 × 4 個角度掃過去，
最擠的一座（3000 塊的美國國會大廈）佔畫面 0.80，一般的落在 0.74，上緣不會頂到工具列。

畫面比例是取景距離的一部分，所以 `resize()` 要重新取景——不然橫式轉直式會把建築切掉。

**霧也要跟著相機走。** 霧是給遠方地平線的，起霧處只綁碎料範圍的話，
相機一退遠建築就泡在霧裡：直式手機看金門大橋要退到 460，而霧只到 316，整座橋會白掉。

## 平移鏡頭（WASD）

WASD 移動的是**旋轉中心**，不是相機本身——相機還是繞著中心轉，只是中心跟著你走。
太陽與陰影目標本來就綁在旋轉中心上，所以平移之後光影會自己跟過去，不用另外處理。

方向以**畫面**為準：相機位在中心的 `(cos yaw, sin yaw)` 方向，所以畫面的「往前」是它的反向。
照世界軸走的話，轉過視角之後按 W 會往螢幕的斜後方跑。

速度跟目前視距成正比（拉遠了還用同一個速度會像在爬），而且用**真實時間**推進——
開四倍速不該讓鏡頭也快四倍。

三個邊界：

- **要夾住**。草地是有限的圓島，中心固定在原點（`setGroundSize` 只設 scale，位置永遠是 0），
  不夾就會平移出去看到虛空。夾在碎料散落範圍內，剛好能走到料場邊。
- **換建築要歸零**，否則新的那座在畫面外。
- **失去視窗焦點要放開按鍵**。按著 W 切去別的視窗，`keyup` 收不到，切回來鏡頭會自己一直飄。

只擋下拉選單的鍵盤事件（字母鍵在 `select` 上是拿來跳選項的）；滑桿與核取方塊吃的是
方向鍵與空白鍵，跟 WASD 不衝突，一起擋掉的話「剛拉完滑桿就按不動鏡頭」反而莫名其妙。

陰影不用另外補償：平移到底時建築離陰影中心 38.9，還在半徑 55.9 的範圍內；
落在範圍外的對岸夠遠，已經被霧蓋掉。**手機沒有鍵盤，這個功能是桌機限定**——
雙指現在是縮放，要加觸控平移得跟 pinch 共存，那是另一件事。

## 小人

身高 `1.06–1.24`，每個人略有不同（積木邊長是 0.94，所以大約是一個半積木高）。
搬東西時**舉的高度要乘上身高**——寫死一個高度的話，高個子的積木會陷進自己的安全帽裡。

沒事做的時候走的路跟施工中分開：`pick`／`build` 本來就得走進工地擺積木，
閒晃則是要繞開已經蓋好的建築。把建築當成以工地中心為圓心、半徑 `siteR` 的一根柱子，
外圍留 1.5 的距離繞過去——要的是「不從建築中間穿過去」，不是貼著每一塊積木算精確的邊。

- 快貼到牆又還朝著中心走：把方向**掰到切線上**，離牆越近掰得越兇。
  直接煞停的話他會頂著牆原地發抖。
- 人已經在建築範圍內（剛擺完積木站在外圈就是這樣）：先往外走出去。
- 目標點落在建築裡：先推到外圈。不推的話他會繞著建築打轉永遠抵達不了，
  也就永遠不換下一個目標，等於卡死在那一圈上。

走到定點會站著發呆一會兒，站多久跟**剛走完**那段路成比例（1.7–3.1 倍，平均 2.4）。
量出來任一瞬間大約**七成的人站著不動**。兩個都是刻意的：

- 用比例而不是寫死秒數——換一座大的（工地大、走得久）站著的人就變少，比例會跟著建築跑掉。
- 算「剛走完」而不是「接下來要走」——後者會讓剛擺完積木的人先在工地正中央發呆快十秒才動身。

## 破壞道具

工具列在畫面**上方中央**，視窗不夠寬就整排搬到底部、只留圖示。

斷點是量出來的 **1500**：十一種道具排一排要 760px，左上的建築資訊卡玩久了會撐到 354px
（累計金額變成七位數那一刻），右緣落在 368；工具列置中，左緣是 `(視窗 − 760) / 2`，
要閃過 368 得有 1496 以上。手機寬度下底部那一排也放不下十一顆（390px 扣掉兩角的
版本號與設定鈕只剩約 246px），所以限寬讓它自己折成兩排。

會爆炸的四種（定時炸彈、隕石、核彈、爆裂魔法）走同一個 `explode()`，

推土機是「砸」不是「炸」，砸出來的碎料不起火。詳見〈放火〉那節的後半。

### 龍捲風

漏斗 **34 高**、撐 **7 秒**，可以**同時存在 4 道**（再丟就把最早那道擠掉）。

- 漏斗是一疊會各自轉、各自偏移的開口圓筒。段與段刻意只疊 35%：接縫留下的那一圈圈橫紋
  就是「它在轉」的線索，疊到糊掉會變成一個乾淨的半透明圓錐，反而不像龍捲風。
- **一層一顆 `InstancedMesh`，每道龍捲風在每層占一個 instance**。濃淡是逐層不同的
  （材質不同，併不起來），但同一層不管場上有幾道都只吃一個 draw call——
  所以總成本固定 16 個，不隨道數增加（實測一道 28、四道也是 28）。
- 起始方向刻意偏 ±0.7 弧度、起始旋轉相位隨機。都精準對著工地中心、都從 0 度開始的話，
  幾秒後會疊成一團而且擺出一模一樣的姿勢，看起來像複製貼上。
- 塵霧的量會隨場上道數遞減（除以 √n）：塵霧總量有上限，全開火的話迴圈先跑到的
  那幾道會把配額吃光，排最後那道變成沒有煙的空殼。
- 拉高之後漏斗頂會頂出畫面上緣（矮建築取景近，實測 NDC 1.45），所以跟蘑菇雲同一套：
  作用期間鏡頭退開（實測 52.6 → 64.5，頂端 NDC 0.71），結束後自己收回原本的取景。

### 放火

它沒有「一下」——威力全在蔓延。點到的那一塊起火，火沿著格子傳給鄰居，
一塊燒到底就焦黑、鬆脫掉到地上，燒穿地基的話上面照樣靠垮塌自己塌。
放著不管，一棟 1120 塊的城堡大約一分鐘燒掉六成（實測 40 秒剩 448 塊）。

- **不另外開網格，0 個 draw call**：燒起來的樣子是「積木的目標色往焦黑收」＋幾顆火苗（`hot`）
  ＋一點深色的煙（`dust`），三樣都是現成的東西。
- **蔓延用 26 鄰居（含斜角）**，跟支撐判定共用同一份 `NBR`。voxel 造型很多是斜線畫的
  （鐵塔的斜撐、螺旋、圓弧），只認 6 面的話火會在斜著相鄰的地方整片停死。
  每次只傳給**一個**鄰居、而且 `NBR` 從隨機位置開始繞——固定順序的話火會一路往同一個
  方向鑽，變成一條線不是一片。
- **每塊燒的快慢各抽一個 0.8–1.3 的倍率**。全部同速的話整面牆會同一秒一起變黑、
  一起掉下來，看起來像在播動畫不像在燒。
- **焦黑要設在 `breakBlock` 之後**：`freeBlock` 會把目標色打回建材色（碎料就是建材），
  設在前面的話積木一掉下來就恢復原本的顏色，「燒黑」等於白做。這是實際踩到的坑，
  現在有一條測試守著它。
- **還站著的同時最多 150 塊在燒**（碎料的火另有一份額度，見下），火苗的配額再除以
  √(在燒的塊數)：火苗跟爆炸的火球共用同一個粒子池，整棟在燒時把池子吃光的話，
  這時候丟一發核彈就會沒有火球。
- 火會**燒到沒得燒就自己滅**（鄰居都燒完了、或中間被垮塌挖出一段空隙）。想燒完整棟
  就再點一次別的地方。
- 換建築時**火要收掉**：燒的是「哪一塊積木」，而積木會被回收去蓋下一座——
  不收的話新建築會從某幾塊莫名地開始燒起來。

爆炸類（炸彈、隕石、核彈、魔法，都走 `explode()`）炸完會留下**兩種火**：

- **還站著的**（`SET`）：半徑放到 1.5 倍去找，限量 `R×0.8` 塊、每塊三成機率。
  半徑放大是因為衝擊圈內的積木幾乎都被炸飛了，還站著的都在圈外那一帶。這些會繼續蔓延。
- **這一發打出來的碎料**（`FLY`）：**每一塊都燒**，固定 3 秒，不抽快慢倍率。拖著火飛出去、
  落地是一塊焦炭。不蔓延（它已經離開建築了，沒有鄰居可傳），燒完也**不會再被打掉一次**——
  建築那種火燒完會 `breakBlock` 讓它鬆脫掉下來，碎料本來就躺在地上，再打一次會看到它
  自己彈起來，所以那段用 `f.sp` 擋掉了。

碎料的火在 `explode()` 那個迴圈裡**逐塊點**，不是事後用 `igniteAround` 撈：「被這一發炸到的」
就是那個迴圈掃到的那些，事後撈得再掃一次全部積木，而且分不出哪些是早就躺在那裡的舊碎料。

兩種火的**額度是分開的**（`FIRE_MAX` 150 vs `EMBER_MAX` 3000）。共用一份的話，一發爆炸打出來的
上千塊碎料會瞬間吃光額度，旁邊沒倒的那半棟就再也燒不起來——那才是這個道具最該看到的畫面。
碎料的額度開到 3000（等於整個積木池）是因為核彈半徑 30 幾乎蓋住整棟：實測中世紀城堡 2924 塊
裡有 2511 塊在範圍內，額度低於這個數字的話，同一發爆炸會有一批碎料沒燒，看起來不像設計、
像額度用完了。

- **成本**：2511 塊碎料在燒的當下 step 0.40ms + draw 0.44ms（預算 4ms），**0 個 draw call**——
  焦黑是改積木自己的目標色，火苗與煙都是現成的粒子池。
- **火苗的配額從隨機的地方起跳**（`em: Math.random()`，原本是 0）。同一幀點著上千塊、配額
  又一律從 0 開始的話，它們會同時湊滿第一顆火苗：火變成「整片一起閃、然後一起沒有」。
  實測沒做這件事時火苗數在 0～94 之間跳，做了之後穩定在 170 上下。

還有一個先天限制：核彈／魔法把整棟夷平時，下一幀就會觸發「剩不到 25% 換下一座」，
換場會把火一起收掉，所以那種情況的餘火只閃一下。想看火燒建築就用**放火**，
或把核彈打在邊邊、打**比範圍大的地標**（萬里長城、金門大橋）。

### 隕石

點一下 → 地上一圈一圈地標 3 秒 → 一顆燒紅的石頭從斜上方 **45°** 插下來 → 落點一帶起火。
範圍是投石機石頭的**兩倍**（`MET_R = ROCK_R × 2` = 9.2），威力 16 介於石頭（12）與
定時炸彈（17）之間。**同時最多 6 顆**，每顆各自從一個方位進來、倒數也各走各的。

- **45° 是同一個變數算出來的**：「水平還要飛的距離」跟「還沒掉的高度」共用一個 `up`，
  所以不管尺度怎麼變，角度永遠是 45°。等速直線，不走拋物線——隕石不是被丟出來的。
- **從 62 高的地方進來，掉 0.9 秒**。實測 0.55 秒（六成的行程）都在畫面內；
  更高就變成核彈那樣（130 高）大半段在畫面外，更低就沒有「從天上來」的感覺。
- **半路撞到建築就當場炸開**，跟投石機的石頭共用同一套掃掠判定（`sweepRock`）。
  斜插進來的東西只在終點判定的話，會從屋頂穿過去才炸（實測落點指在 y=0.6、
  實際炸在帝國大廈的 y=13）。
- **只吃 2 個 draw call（主畫面＋陰影），而且只在真的飛的時候**。倒數中的那幾顆連影子
  都不該有，所以 `draw()` 把「在天上的」濾出來再交給畫面層（濾用的陣列是重用的，
  不每幀配置）。陰影那個 call 是值得付的：落地前地上那塊影子剛好提示它要砸哪裡。
  六顆一起飛也還是 2 個——一顆一個 instance。
- **火焰是粒子，不是那顆石頭**。石頭本體刻意壓暗（燒紅的岩石），亮橘色的石頭
  在陽光下只會像一個橘色箱子。火苗三顆裡有一顆生在**石頭四周**（不是沿著路徑、
  也不是正中央——生在中央會被那顆立方體擋在後面）而且大顆短命，整圈把石頭包起來；
  其餘小顆的沿著這一幀走過的線段撒，尾巴才不會斷成一節一節（它一幀跑五個單位）。
  後面再拖一條深色的煙（`dust`，往上飄）撐出尾巴的長度。
- **落點的火比爆炸自帶的餘火多**：`explode()` 之後再點一次 `R×1.6` 範圍、`R×1.6` 塊，
  這是它跟同尺寸普通爆炸最明顯的差別（實測落地當下有 22 塊「還站著的」在燒，
  兩秒後蔓延到 68 塊；炸出來的碎料另外全部都在燒）。

### 倒數型道具

後面四種的共通點是「點下去不會馬上炸」，所以每一種都得讓你在等待期間看得出**它在等**、
而且**等一下會炸到哪**：

- **定時炸彈**：頂端的燈一明一滅並嗶聲，越接近爆炸越急。
- **隕石**：倒數那 3 秒在落點打一圈氣霧、每半秒一圈並嗶一聲；進大氣層才開始畫、才有呼嘯聲。
- **核彈**：倒數那 2 秒在地面打一圈氣霧當標記。什麼都不畫的話，前兩秒看起來就像點了沒反應。
- **爆裂魔法**：陣是**六層疊起來**的，不是同心圓——整疊都浮在半空
  （最下層離地 12、最上層 34.6，整疊高 22.5），中間收窄、最上面那層再放大一點。
  高度是**照著「太扁平」的回饋拉上來的**：最寬那圈直徑就有 37，疊得比它矮的話
  遠看是一疊盤子不是一座法陣。拉高之後整疊頂端會頂出畫面上緣（矮建築取景近），
  所以跟龍捲風、蘑菇雲同一套：**施法期間鏡頭退開**（`holdWide(66, 7)`，
  實測吉薩金字塔視距 42 → 66，頂端 NDC 0.65），爆完那朵蘑菇雲接著撐住同一個距離。
  最下層刻意不做滿爆炸半徑：做滿的話那一圈會比建築大一大圈，
  看起來像地上的跑道而不是浮空的陣。代價是「最外圈就是爆炸範圍」這個提示沒了。
  每 0.8 秒長一層、**出現順序每次施法都洗牌**（Fisher–Yates 洗 `ord`，洗的只是
  「哪一層什麼時候出現」，每層自己的高度與半徑不動）——固定由下往上長的話，
  那六秒每次都長得一模一樣。
  **位置一開始就在它該在的高度，只有半徑從 12% 擴到滿**——
  高度也跟著長的話，看起來是「從地上飄上去」而不是「在那裡展開」。
  半徑刻意**不照大小排**（由大到小再放大會太像規矩的陀螺），而且每次施法
  各層再乘一個 0.82–1.18 的抖動——抖動在**施法當下抽一次**存起來，
  每幀重抽的話整疊會一直閃。
  每一層由**四樣東西**疊出來：填滿的盤、實色的芯環、加法混色的暈環，
  再加上盤面的**螺旋紋路**（兩組反向的螺旋臂 + 一圈虛線，129 個 instance
  但只吃 1 個 draw call）。螺旋是把每條臂切成幾段短棒沿曲線擺出來的——
  直的放射線看起來像車輪，參考圖是捲進去的漩渦。中心那顆亮核不用另外畫：
  所有臂的內端都收在中心附近，加法混色自然就亮成一顆。
  **陣會逆時針慢慢轉**（0.42 rad/s，每層再各乘 0.7–1.35 的倍率——同速的話整疊像
  一塊剛體在轉）。起始角度每層還是各抽一個定值：六層都從同一個角度起跳的話螺旋會對齊，
  整疊看起來像一支花紋對齊的柱子。
  方向這件事**不能只看角度變大變小**：紋路是用 `(cos a, sin a)` 擺到 `(x, z)` 上的，
  而畫面看下去 `+Z` 朝下，所以 `a` 變大在畫面上反而是順時針。實測（把場上真的畫出來的
  那段紋路投影到畫面，算外積）：`a` 遞增是 −0.0067（順時針），改成遞減才是 +0.0058
  （逆時針）。同理，引擎裡兩組螺旋與外圈虛線的角度倍率原本有負的（陣不轉時那只是
  讓它們錯開的相位差），現在一律取正，不然會有一組逆著整個陣往回轉。

### 爆炸的向量

跟槌子的差別是「沒有揮擊方向」。衝擊波是球狀的：方向取「炸心 → 積木」的**三維單位向量**，
再疊一股往上的抬升。抬升跟「離炸心多近」成正比（`f × 0.85 × 接近度`），
所以越靠近的拋得越高——實測最高飛到 44、滯空 3.6 秒，落地才有明顯的拋物線。
只給徑向的話積木是貼著地面往外掃，看起來像被推倒不像被炸飛。

垂直分量一律取正（用 `|dy|`）——照落差的正負給的話，炸點底下的積木會被往地面壓，
看起來像陷進地裡。

半空中的碎料（`FLY`）也吃得到衝擊波，只有小人手上的不動。
漏掉飛行中的話，魔法陣先吸到陣心的那堆碎料就不會被噴出去，
「先收縮後爆發」會變成「吸過來然後靜靜落地」。

### 引力坍縮（爆裂魔法）

這是它跟核彈最大的差別：核彈是「一下打平」，魔法是**先聚成一團再炸開**。

- 倒數剩 **4.5 秒**開始吸周圍的碎料（**內吸 + 切線 = 螺旋**），越接近爆炸吸得越猛，
  同時從陣的外圈撒出往中心捲的魔力光點。實測碎料離陣心 21.2 → 14.2。
- 倒數剩 **2.2 秒**開始**連建築本身都一塊塊扯下來捲進去**（每塊每秒被扯下的機率
  從 0 爬到 2.6，所以是「開始鬆動 → 整棟被拆著吸進去」而不是一次全開）。
  只吸散落的碎料的話，打在完好的建築上幾乎看不到收縮這段——地上根本沒有碎料可吸。
  實測 2216 塊的城堡在爆炸前只剩 101 塊站著，碎料平均離陣心 4.1（建築本身原本是 5.4）。
- 六秒一到火球把它們全噴出去：實測離陣心 4.1 → 一秒後 26.6，最遠 38.9。

扯下來的積木照樣走 `freeBlock`／`afterHit`，所以進度、損失、擊飛數都算得到；
`afterHit` 的半徑給 6（陣心那一圈）而不是 30，不然整個工地的小人會每一幀被掀倒一次。

**陣還在充能時不換下一座**：扯的過程一定會跌破「剩不到 25% 就換場」那條線，
照換的話 `startBuild` 會把陣一起收掉，那一發永遠等不到爆炸，玩家只看到建築憑空消失。

三個倒數型道具都會在換建築時一起收掉，否則上一輪的倒數會炸到剛蓋好的新那座。

### 爆炸特效

一發爆炸是三層疊出來的：**中心一顆白熱的火球**、**從球面往外噴的火星**、
**貼地掃出去的兩圈光環**。核彈與魔法接著再長一朵蘑菇雲。

火球本體是**實體球殼**，不是粒子。粒子撐不出「一整顆在發光的球」：九十六顆小方塊
再多也是一團碎火，中間該最亮的地方反而因為方塊之間有縫而透出背景。
球殼一次疊五層同心球（半徑 0.40 → 1.10 倍），每層一顆 InstancedMesh、
走加法混色，同時炸幾發都只吃五個 draw call。

- **每層的濃度都壓得很低**（0.50 / 0.30 / 0.22 / 0.15 / 0.09）：加法混色會累加，
  中心是五層疊起來的，總和約 1.26 剛好過曝成白。各層給高一點整顆會平成一片死白，
  黃橘的漸層全看不見。
- **球心抬到爆點上方 R×0.22**：貼著地面生的話會被自己炸出來的碎料堆埋掉——
  它雖然是加法混色，擋在前面的積木照樣不透明。量過：抬起來之後過曝的白像素從
  0.85% 變 3.02%（帝國大廈）、2.17% 變 5.13%（中世紀城堡）。
  抬起來後球的下緣還是切在地面附近，埋在地下的那部分被草地擋掉。
- **半徑走 sqrt、亮度收得更快**：0.05 秒就撐到半徑的一半，0.65 秒收乾淨；
  兩者同速的話它像顆縮回去的氣球，火球是「膨脹的同時燒完冷掉」。

火星（走 hot 那顆材質）**生在球面附近往外噴，不生在球心**。生在球裡的話這些幾乎
不透明的方塊會整片糊在球的正面，把核心遮成一堆橘色碎片，換球殼的意義就沒了。
它不跟煙塵共用材質：煙塵那顆固定 50% 透明（煙就是要透），火混在裡面永遠亮不起來，
看起來只是幾片橘色玻璃。顏色照半徑分：貼著球面的亮黃、噴得最遠的橘，
再隨時間冷成暗紅（魔法版冷成暗桃紅）。

蘑菇雲不是一次生出來的：**傘蓋往上升，柱子是它沿路留下來的那一條**。
兩邊都從地面往上噴的話會混成一團胖雲，看不出蘑菇的頸子。腰上那一圈環是參考圖裡
最好認的特徵，所以也做了。

腳下另外鋪一圈**貼地往外滾的煙**（參考圖裡蘑菇雲底部那一圈翻滾的濃煙）。
沒有它的話柱子是從一塊乾淨的草地長出來的，看起來像插在地上。做法跟柱子同一招：
**生成半徑隨時間往外擴**（1.7 秒內擴到 R×0.55），速度只負責近處翻滾，
重力給大一點讓它噴起來後壓回地面貼著滾。它的塵霧配額壓在 430、比柱子與傘蓋的 520 低——
傘蓋是 0.45 秒一次要 112 顆的爆量，煙裙要是先把配額吃光，蘑菇會變成一根沒有頭的柱子。

三個實作上的坑：

- **橫向擴散只能靠「生出來時就在那個位置」**：粒子每幀乘 0.94 的阻力，
  橫速不到一秒就歸零，給再大的初速也只多跑一兩單位。
- **慢慢消失要用縮的**，單靠壽命到期會「啪」地整團同時不見。
- **雲頂會升到 40 以上，鏡頭裝不下**：取景是照建築算的，中型建築的畫面上緣大約在
  高度 25，不處理的話只看得到那根柱子。所以引爆時**鏡頭會退開**（視距 ×2.2、
  視線抬高），七秒後用最後一次取景的參數自己收回去。
  一發核彈常常把整棟夷平而立刻換場，換場的重新取景在運鏡期間不准把鏡頭收回來，
  否則雲會被拉出畫面。

火球、蘑菇雲、光環**不**在換建築時清掉——它們純粹是畫面，不會動到積木。
一發核彈常常直接把整棟夷平，那會立刻觸發「剩不到 25% 就換下一座」，
清掉的話蘑菇雲會在爆炸後 0.05 秒整朵消失，等於白做。

## 成就與紀錄

十九個成就，分成四組，每組都有「入門」跟「下一階」兩個門檻：

| 組 | 成就 |
|---|---|
| 蓋 | 開工大吉、奇蹟工程、大興土木、環遊世界 → 地標蒐藏家、愚公移山 → 工蟻軍團 |
| 拆 | 拆遷大隊 → 一發清空、粉塵滿天、拆屋大亨 → 都市更新、工具箱清空 |
| 小人 | 工頭嚴厲 → 工安黑名單 |
| 錢 | 百萬工程 → 無底錢坑、災情慘重 → 保險公司拒保 |

面板排兩欄（手機一欄），同一件事的兩個門檻並排，一眼看得出「這個拿到了、下一階還沒」。

還有兩筆錢：

| | 怎麼算 | 顯示在 |
|---|---|---|
| **人力金額** | 每個小人每秒 $3，只在施工中累積，開倍速就燒得更快 | 左上角 |
| **破壞損失** | 每塊從建築上掉下來的積木 $85 | 右上角（紅字）、成就面板 |

損失不管你怎麼弄掉它都算：槌子打飛的、龍捲風吸走的、失去支撐自己垮下來的，
還有拆到門檻時剩下沒打到、跟著整棟報廢的那些。單純從面板換一座建築不算損失。

程式上記在 `freeBlock` 裡——那是「已就位的積木離開建築」唯一的出口，
所以不會漏掉任何一條破壞路徑，也不會重複計。
一千塊的建築拆完約 $85,000，跟蓋它花掉的人力錢是同一個量級。

紀錄與**面板設定（建材數、小人數、速度、靜音、自轉）**一起自動存在瀏覽器的
localStorage，下次打開直接套用，不用每次重調。

存檔格式：JSON → 校驗碼 → UTF-8 → XOR → base64。前端沒有真加密可言，
這只是讓存檔不能隨手改；改壞了校驗碼對不上就整份不採用，不會讓程式吃到爛資料。
設定值讀回來時一律夾回合法範圍。

設定裡有個版本欄位 `v`。預設建材從 900 改成 3000 時，舊存檔裡的 900 分不出是玩家挑的
還是舊預設值——只認「沒有 `v` 欄位」的存檔，把建材換成新預設，換過一次就不再動它。
不做這件事的話，改了預設的人（存檔早就寫過了）永遠看不到 3000。

## 版本號

版本號寫在 `src/game.js` 最上面的 `VERSION`，畫面右下角會顯示。

**每次 commit 都要動版本號**：一般改動 `patch +1`，功能性改動 `minor +1`（patch 歸零）。
改完記得同步這份 README 開頭的版本——e2e 會檢查兩邊一致，對不上就失敗。

## three.js 為什麼要自己打包

官方 build 只出 ES module，而 **ES module 走 `file://` 會被 CORS 擋掉**：

```
Access to script at 'file:///...' from origin 'null' has been blocked by CORS policy
```

雙擊開檔就整支掛掉。classic script（`<script src>`）沒有這個限制，所以把
`three.core.min.js` + `three.module.min.js` 轉成 IIFE 掛到 `window.THREE`。

要換 three 版本時：把原始碼解壓到 `three.js-master/`（此目錄不進 git，576 MB），然後

```
node tools/build-three.cjs
```

打包器會比對對外名稱是否與官方 `three.cjs` 完全一致（441 個），少一個就直接失敗。

## 跑測試

```
node tools/e2e-3d.cjs
```

需要 Playwright 與 chromium；找不到時腳本會印出安裝方式。全部通過 exit 0。
截圖產物在 `tools/.e2e-out/`（已 gitignore）。

測試一定跑真瀏覽器，因為這支程式的坑都在「真實環境與假物件的差異」：
ES module 的 CORS、canvas 是 replaced element、WebGL 的 drawingBuffer 合成後會被清空。

headless chromium 用 SwiftShader 軟體算圖，所以測出來的 fps 沒有參考價值；
效能那段量的是 CPU 端成本（`step` + `draw`），那個跟顯示卡無關。

## 效能

所有積木共用一個 `BoxGeometry` 走 `InstancedMesh`，不管 300 塊還是 3000 塊都是
**1 個 draw call**；小人的 7 個部位也全塞在同一個 InstancedMesh 裡。
整個場景含陰影約 11 個 draw call。新道具的網格一律「沒在用就 `visible = false`」——
`InstancedMesh` 就算 `count = 0` 也會吃掉一個 draw call，平常不該為了沒放的道具付這個錢。
魔法陣展開的那六秒最貴：六層 ×（盤 + 芯環 + 暈環）各自一個 call，共 31 個，
每幀 CPU 成本 0.74 ms（2925 塊積木同時在場）。
龍捲風是 16 個（一層一顆 `InstancedMesh`），**一道跟四道一樣貴**；
爆炸中心的火球是 5 個（一層球殼一個），同理**一發跟四發一樣貴**；
隕石是 2 個（主畫面＋陰影），六顆一起飛也還是 2 個。
這裡有個坑——**透明的雙面材質，three 預設會分兩趟畫**（先背面再正面），
draw call 直接翻倍。這些是貼平的薄片用不到那個排序，
材質開 `forceSinglePass` 就砍回一半。

實測 CPU 端每幀成本（模擬 + 寫 instance buffer）：

| 情境 | step | draw | 合計 |
|---|---|---|---|
| 969 塊積木 + 20 小人 | 0.01 ms | 0.15 ms | 0.16 ms |
| 2925 塊積木 + 60 小人 | 0.03 ms | 0.36 ms | 0.38 ms |
| 核彈爆炸當下（2925 塊 + 224 顆粒子） | 0.32 ms | 0.37 ms | 0.69 ms |

瓶頸在 GPU 的填充率與陰影貼圖，不在 CPU。

## 已知限制

- **造型品質不齊**。金字塔、艾菲爾鐵塔、台北 101、天壇、金門大橋、城堡、五重塔這些很好認；
  聖母院、獅身人面像最弱。
- **雪梨歌劇院是刻意的簡化，不是照著蓋的**。真實的帆殼是從同一顆球面上切下來的瓣片，
  試過照做（球面切瓣），也試過「斷面是拱、沿長軸長大」的號角，在這個積木尺度下都不行：
  前者切出來是又窄又薄的刀片，後者從斜上方只看得到兩片側壁，像石柱。
  最後用的是「一排由小到大、頂端收尖的半殼，底座只相切不重疊」——認得出來靠的是排列
  跟一片比一片高，不是單片曲面正不正確。重疊多一點就會融成一坨土丘，這點試錯了五版才定案。
- **小尺寸貼不齊**。像台北 101 有八節、吳哥窟有五塔、農神五號連發射塔架，造型本身就有
  最少積木數，設 400 塊時它們給的是 600～700 塊（最誇張的農神五號 684）。
  預設的 3000 塊那一檔 36 座都在 5% 以內，中間的 1500 最差 −11%（吉薩金字塔——
  方錐的塊數是奇數平方和，階距天生就粗）。HUD 一律顯示真實塊數。
- **垮塌只看「連不連得到地面」，不算力矩**。所以往外伸很長的懸臂只要還連著就不會斷，
  真實建築早就折了。支撐關係算 26 鄰居（斜角接觸也算），因為很多 voxel 造型
  是用斜線畫的——只認 6 面的話艾菲爾鐵塔會有 1205/1225 塊被判成懸空，判定等於失效。
- **積木之間沒有碰撞**。碎塊落地後只做水平分離避免重疊，不會堆疊成山。
- **龍捲風很強**。一發常常能吃掉一整座建築的大半，還可以同時來四道。
  嫌太猛就調 `game.js` 的 `TW_R`（作用半徑）、`TW_LIFE`（秒數）或 `TW_MAX`（最多幾道）。
- **拆除門檻是寫死的 25%**（`game.js` 的 `WRECK_AT`）。拆到剩 25% 以下就換下一座。
- **整地不是把地掃乾淨，是把堆起來的推開**。三台機器六秒半推得動一兩百塊；
  碎料鋪滿整片工地時（拿龍捲風或保齡球拆的常常這樣）推不完，
  剩下的收尾時由 `kickOutSite` 往外拋出場。這是換場的空檔不是關卡，
  不值得為了幾百塊讓玩家多等十幾秒。
